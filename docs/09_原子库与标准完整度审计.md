# Samskill 公开原子库与标准完整度审计

审计日期：2026-08-14。
审计对象：`Samskill 1.0.0-beta.4` GitHub 公开测试包

## 先说结论

beta.4 已经加入可公开检查的原子库，不再只是“从原子库编译出的运行子集”。

当前公开包同时具备：

- 18 个可独立安装的 Skill。
- 17 个方法模块。
- 203 张 `SAM-*` 方法原子。
- 78 张可公开来源证据卡。
- 1 张只登记、不复制正文的受限来源卡。
- 5 份根级统一协议。
- 514 条原子到 Skill 的追踪关系。

它达到的是“可安装、可追溯、可审核、可以进入真实测试”的公开 Beta。

它还不是经过大规模陌生用户和多项目结果验证的稳定版。

## 一｜公开包的两层结构

### 运行层

`skills/` 保存一个总入口和 17 个专项 Skill。

每个 Skill 保留独立运行所需的输入卡、输出模板、流程规则和裁剪资料。

单独复制一个 Skill 时，不会因为根级原子库缺失而立即失效。

### 知识真源层

`knowledge-base/` 保存公开的方法原子和证据登记。

`standards/` 保存多个 Skill 共同使用的证据、案例、时效、优先级和渐进加载规则。

这层用于解释结论、复查来源、提交修订和定位错误，不会在每次任务里全部进入模型上下文。

## 二｜当前数量

| 项目 | 数量 | 当前作用 |
|---|---:|---|
| Skill | 18 | 实际调用与交付 |
| 方法模块 | 17 | 组织整个一人媒体与自然流工作链 |
| 方法原子 | 203 | 解释、判断、行动与验证 |
| 公开来源卡 | 78 | 说明来源关系、边界与缺口 |
| 受限来源登记 | 1 | 保留证据缺口，不复制第三方 Skill 正文 |
| 原子—Skill 关系 | 514 | 追踪当前引用和候选关系 |
| 根级统一协议 | 5 | 管理跨 Skill 一致性 |

## 三｜514 条映射不能怎样理解

`knowledge-base/atom-skill-map.csv` 有两类关系：

- `explicit_runtime_reference`：当前 Skill 的运行资料已经明确出现该原子编号。
- `module_scope_candidate`：该原子与 Skill 的职责相关，但尚未证明当前运行一定调用。

当前统计：

- 明确运行引用：309 条。
- 模块职责候选：205 条。

因此不能用“存在映射”冒充“运行时已经加载”。

真实测试出现错误时，应继续检查：

1. Skill 是否明确加载了正确运行资料。
2. 原子是否适用于当前输入和场景。
3. 来源证据能支持到什么强度。
4. 用户材料、任务路由和输出合同是否正确。

## 四｜公开净化边界

公开版删除或不收入：

- 本机绝对路径、账号、联系方式与组织身份。
- 客户身份、合同、付款、后台原件和未脱敏项目文件。
- 内部评审对话、版本比较和重复研发记录。
- 未确认再分发权限的第三方 Skill 正文。
- 第三方书籍、论文、课程和文章全文。

公开来源卡只保存必要的书目信息、理论关系、叁木吸收方式、适用边界和待补证项。

## 五｜当前仍不完整的地方

### 真实交付样例

还没有做到 18 个 Skill 各有一份完整、脱敏、带执行结果的金标准样例。

### 前向验证

三个真实项目还没有全部完成从诊断、执行到复盘的连续验证。

### 候选映射收敛

205 条模块候选关系需要在真实调用中确认、删除或改成明确引用。

### 来源强度

部分来源卡仍是精读摘要、维护者材料或待回填证据，不能当作审计级事实。

### 时效内容

平台规则、法律、价格、行业数据和 AI 能力需要持续核验当前官方来源。

## 六｜什么情况下可以进入稳定版

至少需要：

1. 三位未参与研发的用户独立完成安装与首次调用。
2. 三个真实项目完成诊断、内容任务、发布、承接和复盘链路。
3. 18 个 Skill 各有一份完整脱敏交付样例。
4. 候选原子映射根据真实运行完成第一轮收敛。
5. 记录失败、回退、再次运行和结论被推翻的样本。
6. 来源、版权、隐私与项目证据完成一次独立人工复核。

## 七｜最终判断

如果问题是“现在能不能公开安装测试”：可以。

如果问题是“公开包有没有净化后的原子库”：有。

如果问题是“是否把私人原子库和客户资料全部公开”：没有，也不应该。

如果问题是“203 张原子是否每次自动全部参与运行”：不会，也不应该。

如果问题是“现在能不能称为成熟稳定 V1”：还不能。当前最准确的状态仍是 Public Beta。
