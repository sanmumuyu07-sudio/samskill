# 叁木原子库到 Skill 的引用与渐进加载协议 V1.0

## 核心原则

原子库负责保存完整知识。

Skill 负责识别任务、组织对话、调用所需知识并交付结果。

不能把整座原子库复制进每一个 `SKILL.md`。

那样既浪费上下文，也会让不同 Skill 产生重复版本和相互冲突的规则。

## 三层加载

### 第一层｜SKILL.md

只保存：

- 触发条件。
- 用户入口。
- 运行阶段。
- 必须遵守的判断顺序。
- 输出合同。
- 风险与回退。
- 应加载哪些 references。

### 第二层｜references

按任务加载：

- 模块 Skill-ready 运行包。
- 相关原子正文。
- 工具模板。
- 案例与证据协议。
- 叁木写作和判断标准。

### 第三层｜scripts 与 assets

只放确定性的机械工作：

- 扫描文件。
- 生成索引。
- 检查元数据。
- 校验链接。
- 保存项目状态。
- 输出固定模板。

脚本不替代市场、用户、内容和商业判断。

## 推荐 Skill 目录

```text
samskill-name/
├── SKILL.md
├── references/
│   ├── runtime-contract.md
│   ├── method-atoms.md
│   ├── tool-contracts.md
│   ├── cases.md
│   ├── output-golds.md
│   └── source-map.md
├── scripts/
└── assets/
```

## 单次任务加载顺序

1. 判断用户属于新项目、已有项目诊断，还是单任务执行。
2. 读取项目状态，避免重复问答。
3. 加载一个主模块运行包。
4. 只加载与当前判断相关的 1—3 张原子。
5. 需要填写时加载一个工具合同。
6. 需要解释时加载一个主案例和必要反例。
7. 输出后保存结论、证据、未决问题与下一路由。

## 禁止重复

- 原子正文只在原子库维护一个真源。
- Skill reference 可以摘录必要规则，但必须登记来源原子 ID 和版本。
- 金样本可以进入 Skill，但不得反过来成为方法原理的唯一来源。
- 同一判断在多个 Skill 中复用时，引用共享 reference，不复制改写。

## 版本依赖

每个 Skill 至少登记：

- `atom_library_version`
- `runtime_protocol_version`
- `writing_standard_version`
- `case_index_version`
- `last_validated_at`

## 首批 Samskill 运行链

### 新项目诊断

01 媒体必要性 → 03 项目起点 → 02 市场 → 04 产品 → 05 用户 → 06 定位。

不要求所有用户完整走完；在主问题已经清晰时停止前置诊断。

### 账号与内容方案

06 定位 → 07 平台 → 08 对标 → 09 选题 → 10 包装 → 11 脚本 → 12 传播。

### 运营与复盘

13 生产 → 14 数据 → 15 经营结果 → 回流 06、09、10、11。

### AI 与资产化

16 读取以上稳定状态，把重复任务交给 AI；不把未验证判断自动化。

### 行动闭环

17 在用户停滞、反复学习或重启时介入，并把现实反馈送回对应业务模块。

## 质量门

Skill 发布前必须通过：

1. 触发测试：该触发时触发，不该触发时不触发。
2. 路由测试：信息充分时不问卷轰炸，信息不足时不凭空生成。
3. 判断测试：有证据、有反例、有适用边界。
4. 交付测试：用户知道现在的问题和下一步。
5. 状态测试：下一轮可以接着做，不从零开始。
6. 安全测试：高风险动作由人确认。

## 与官方 Skill 规范的关系

本协议采用渐进加载、`SKILL.md + references + scripts + assets` 的结构思想。

叁木原子库额外增加项目状态、跨模块路由、证据等级和现实结果回填，使它适合长期自媒体经营，而不只是一次性提示词调用。
