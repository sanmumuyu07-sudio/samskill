# 原子模板与证据规则 V3

> V3 成熟度与完整 K5 模板以 06_叁木原子库K5撰写标准 为准。本文件保留来源、证据和主题章规则。

## 一、原子库最终写谁的判断

最终进入方法原子和主题章正文的，只能是叁木已经重新判断过的内容。

正文不使用下面这种写法：

- 某个人说。
- 某本书认为。
- 某个 Skill 总结。

这类信息只进入来源层和证据层。

正文使用下面这种写法：

> 在什么条件下，什么动作通过什么过程，更可能产生什么结果。

这句话必须同时满足三项：

1. 叁木能解释它为什么成立。
2. 叁木能说清它不能用到哪里。
3. 叁木能把它变成判断、动作和验证。

外部理论帮助我们少走弯路。

成熟案例帮助我们看见市场上真实存在的组合。

它们都不能替叁木完成最后判断。

## 二、原子库分成三层

### 第一层：来源原子

来源原子保存别人说过什么、真实项目发生过什么、平台当前规定什么。

它不急着得出方法结论。

来源可以来自：

- 叁木原话与长期思考。
- 项目后台、订单、咨询、访谈和复盘。
- 平台官方规则和监管文件。
- 原书、原始论文和权威行业方法。
- 外部创作者的完整原文与公开经营材料。
- 外部 Skill 与其他二手摘要。

来源原子只回答：

> 这份材料是什么，它最多能证明什么，不能证明什么。

### 第二层：方法原子

方法原子是叁木已经完成判断的最小方法单元。

它必须能够独立回答：

- 用户遇到了什么问题。
- 叁木怎样判断。
- 为什么这样判断。
- 用户接下来做什么。
- 什么情况下不能这样做。
- 结果回来以后怎样修正。

### 第三层：主题章

主题章围绕一个真实任务，把多个方法原子组织成完整解决路径。

它不是原子卡的拼接。

它要让用户从处境进入，最后拿到判断和行动。

## 三、外部知识进入叁木体系的六步

### 第一步：还原原义

先确认原作者、原书或平台到底说了什么。

中文转译、书摘、二手解读和 AI 蒸馏必须分开。

不能拿二手摘要里的改写句，当成原作者原话。

### 第二步：放回原场景

确认这条观点原本解决什么问题：

- 投资。
- 创作者商业。
- 企业营销。
- 广告回应。
- 心理实验。
- 平台治理。

原场景不同，不能直接互相替换。

### 第三步：提取关系

删除人物名字和专属表达。

只保留：

- 前置条件。
- 关键动作。
- 中间机制。
- 可观察结果。
- 失败边界。

### 第四步：寻找独立样本

至少再找一种不同来源：

- 另一套独立理论。
- 另一个成熟商业样本。
- 叁木真实项目。
- 一个能够反驳它的失败案例。

多个作者互相引用，不算多个独立来源。

一个人在不同平台重复同一观点，也不算多个样本。

### 第五步：形成叁木命题

叁木命题不是折中总结。

它要解决叁木体系里的一个具体问题。

合格命题必须：

- 能被反驳。
- 有适用范围。
- 有判断信号。
- 能产生不同动作。
- 能被真实结果升级或废弃。

### 第六步：进入前向验证

先把命题变成最小实验。

没有前向结果时，知识正文可以达到 K5，但验证等级只能停在 V0—V1。

只有在多个明确条件中重复得到支持，验证等级才可能进入 V3 以上。

## 四、五种内容状态不能混写

### 1. 外部主张

某个作者、理论、平台或操盘手明确提出的内容。

它只证明“对方这样说”。

### 2. 观察事实

材料可以直接确认的现象、数据和动作。

它不自动证明原因。

### 3. 机制推断

多个事实共同支持的一种解释。

它必须保留替代解释。

### 4. 叁木暂定命题

叁木已经完成原义核对、案例比较和边界判断，但仍需要前向验证。

### 5. 叁木执行标准

命题已经被翻译成输入、判断、动作和回填要求。

未来 Samskill 调用的是这一层。

```yaml
---
source_id: SRC-SAM-2023-001
title: 2023知识付费矩阵项目复盘
source_type: 项目一手复盘
owner: 叁木
date: 2023
captured_at: 2026-08-11
original_path: 绝对路径或网页链接
rights: 私有可内部使用
evidence_grade: B
verification_status: 待后台与订单补证
supports:
  - 五人团队可以稳定执行矩阵生产流程
  - 项目存在公域到私域再到成交的链路
does_not_support:
  - 所有成交由内容团队造成
  - 该模式对所有业务有效
  - 公开可核验的利润结论
themes:
  - 矩阵
  - 团队交接
  - 知识付费
---
```

正文保留：

1. 原文、原始材料或忠实摘要。
2. 数据口径。
3. 已知缺口。
4. 可以支持的结论。
5. 不能支持的结论。
6. 与其他来源的冲突。

主题章正文可以讲公开案例。

但案例只负责让机制变得具体。

不能让人物身份替代判断本身。

## 八、证据分级

### 来源等级

| 等级 | 来源 | 能承担什么 |
|---|---|---|
| A | 官方规则、监管文件、原始后台、订单、合同、原书原文、原始论文 | 直接事实或原始理论 |
| B | 当事人完整访谈、一手项目复盘、权威第三方调查、可重复观察资料 | 事实补充和机制推断 |
| C | 书籍摘要、书籍精读摘要、外部 Skill 原子、行业报告、完整二手案例 | 研究线索和框架候选 |
| D | 单条短视频、朋友圈、评论、匿名讨论、营销海报 | 发现问题，不承担核心结论 |
| U | 无来源或无法确认 | 禁止进入成熟区 |

市场成功不是单独的证据等级。

一个人赚到钱，证明他的整体组合在某些条件下成立。

它不能证明他对结果的每一种解释都正确。

### 结论状态

| 状态 | 含义 |
|---|---|
| 事实 | 来源直接支持 |
| 推断 | 多项事实共同支持，但没有被直接确认 |
| 假设 | 准备通过新材料或实验验证 |
| 未知 | 当前没有足够证据，停止补全 |

### 成熟度

成熟度必须分成 K、E、V 三轴。

权威原书可以提高来源与证据质量。

它不能自动提高真实项目验证等级。

完整定义见：06_叁木原子库K5撰写标准。

## 九、证据冲突怎么处理

两个来源冲突时，不做平均。

依次检查：

1. 是否在说不同平台、阶段、人群或业务。
2. 指标口径是否一致。
3. 一个是事实，另一个是否只是作者解释。
4. 发布时间和平台规则是否已经变化。
5. 双方成功是否依赖不同的商业模式。
6. 能否设计一轮低成本实验区分两种解释。

无法解决时，保留冲突。

不要为了让体系看起来整齐而强行统一。

## 十、强观点怎样进入原子库

“只看利润”“排除自我”“像素级模仿”“先模仿再差异化”一类强观点，不直接删除。

它们先进入条件策略区。

每条强观点必须回答：

- 它在对抗什么常见错误。
- 它在哪个阶段有用。
- 它忽略了什么变量。
- 使用过度会造成什么损失。
- 怎样改写成叁木可执行标准。

例如：

外部强观点：

> 排除一切关于自己的讨论。

叁木处理后：

> 先把真实执行约束与自我辩护分开。前者决定迁移成本，后者只是在延迟行动。

## 十一、平台事实专用模板

```yaml
---
id: PLATFORM-DY-202608-001
platform: 抖音
account_type: 个人创作者
content_type: 自然流短视频
region: 中国大陆
claim: 后台存在某数据字段
source_type: 官方创作者文档或登录后台
source_url: https://...
published_at: 2026-xx-xx
checked_at: 2026-08-11
expires_or_recheck_at: 2026-09-11
status: 已核验
---
```

平台内容分四层保存：

1. 官方规则和真实后台字段。
2. 当前项目的实际数据。
3. 跨账号、跨阶段的经验范围。
4. 等待验证的行业说法。

禁止直接写成平台公理：

- 固定流量池层级。
- 全业务统一完播阈值。
- 固定发布时间。
- 固定内容配比。
- “断更必降权”“换设备必限流”等无法核验的传言。

平台规则发生变化时，只更新平台事实原子。

不直接改写长期稳定的传播与商业原理。


## 十四、原子升级和废弃

每次升级必须记录：

- 新增了什么证据。
- 哪条判断改变了。
- 适用范围扩大还是缩小。
- 哪些下游主题章、模板和 Skill 受影响。

出现以下任一情况，原子应降级或废弃：

- 官方规则改变。
- 新案例持续反驳原结论。
- 原数据口径错误。
- 原书摘要被原文推翻。
- 判断无法产生一致行动。
- 实验结果只适用于一个专属条件，却被写成普遍规则。

废弃不删除。

移动到废弃区，并保留替代原子 ID。
