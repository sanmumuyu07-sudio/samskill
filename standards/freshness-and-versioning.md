# 叁木原子库时效与版本更新协议 V1.0

## 为什么公理和规则必须分开

需求、信任、证据和交易的部分原理可以长期使用。

平台字段、推荐规则、产品价格、AI 能力、监管要求和行业数据会变化。

把两者混在一起，会让过期经验伪装成底层规律。

## 四类知识

### A｜相对稳定原理

例如信息不对称、注意力稀缺、信号、交易成本、用户任务和社会认同。

每年复核一次来源和解释边界。

### B｜经验判断

例如叁木从多个项目提炼的内容生产、自然流获客和承接断点。

每季度结合项目复盘更新，不自动视为普遍因果。

### C｜平台与市场规则

例如平台功能、字段、推荐说明、广告规范、价格和行业供需。

引用时必须标注来源、地区和抓取日期；重大任务执行前重新核验。

### D｜AI 与工具能力

例如模型能力、上下文限制、Skill 格式、权限与接口。

按版本记录；搭建或发布 Skill 前核验官方文档。

## 最低元数据

时效性内容必须包含：

- `source_url`
- `source_owner`
- `retrieved_at`
- `effective_region`
- `effective_version`
- `freshness_class`
- `next_review_at`
- `supersedes`

## 更新频率

| 类型 | 默认复核频率 | 立即复核条件 |
|---|---|---|
| 稳定原理 | 12 个月 | 原始文献、定义或适用边界被质疑 |
| 叁木经验判断 | 3 个月 | 新项目出现相反结果 |
| 平台规则 | 30—90 天 | 功能、政策、流量结构或后台字段变化 |
| 行业数据 | 使用前 | 进入新行业、地区或价格周期 |
| AI 与 Skill 规则 | 发布前 | 模型、工具、权限、官方规范更新 |
| 法律与合规 | 使用前 | 高风险业务、平台处罚或法规变化 |

## 过期状态

- `current`：当前可用。
- `review_due`：到期但没有发现冲突，引用时提醒。
- `stale`：高概率已变化，禁止作为确定结论。
- `superseded`：已有新版本，仅保留历史审计。
- `unknown`：来源或日期不清，只可作为线索。

## Agent 调用规则

1. 遇到平台、价格、政策、人物职位、产品功能和近期案例，默认先核验。
2. 不能联网或没有当前来源时，明确写“待核验”，不补造规则。
3. 任何最新数据都不能直接改写稳定原理，只能更新条件和证据。
4. 更新不覆盖旧判断；保留版本、日期和被替代关系。

## 项目复盘回流

每次真实测试至少回填：

- 当时假设。
- 实际动作。
- 内容与业务结果。
- 与原判断一致或冲突的证据。
- 规则是否需要修改。
- 修改影响了哪些原子、工具和 Skill。
