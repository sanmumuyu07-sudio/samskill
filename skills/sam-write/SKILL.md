# 叁木｜内容创作

## 交付目标

把真实问题、作者判断和证据编码成读者听得懂、愿意继续、能记住且可以兑现承诺的完整内容。

用户离开本 Skill 时必须知道：当前结论、判断依据、只先做什么、怎样验收、失败时回哪里、下一任务是什么。

## 必读与按需资料

启动后先完整读取 `references/sanmu-intake-and-delivery-contract.md` 与 `references/public-io.md`，先确定本轮任务、交付对象、输出深度和五类信息状态。

随后读取：

1. `references/runtime-contract.md`：入口、判断顺序和结束条件。
2. `references/output-contract.md`：用户版交付、状态和交接。
3. `references/method-index.md`：根据当前断点选择原子库运行包、工具和案例。
4. `references/sanmu-content-quality-contract.md`：设计标题开头、推进结构、共鸣表达和作者声音时完整读取。
5. `references/sanmu-writing-standard-v2-runtime.md`：执行写作优先级、中心守恒、论证、对象关系、案例、概念、载体和三通五维时完整读取。
6. `references/content-framework-selector.md`：所有完整创作和框架比较任务必须完整读取。
7. `references/content-form-selector.md`：载体、镜头和呈现形式未确认或需比较时完整读取。
8. `references/content-framework-case-index.md`：需要框架案例时按需读取。
9. `references/reference-adaptation-contract.md` 与 `references/original-reconstruction-contract.md`：输入含参考原文时完整读取，并判断是否必须转 sam-reconstruct 的参考型改写或独立原创重构。

需要追溯理论、版本或原创性时读取 `references/source-map.md`。

需要测试边界时读取 `references/pressure-tests.md` 与 `evals/evals.json`。

只加载当前任务所需资料，不一次读完全部 references。

追问、暂定判断、阻断确认、正式方案和状态交接必须遵守共用输入与交付协议。不要把内部推理、Skill 名或原子编号写进客户正式方案。

读取旧项目文件时，旧工具名、旧评分公式和旧强制调用链只视为历史材料。

不得要求用户安装、调用或等待任何 Samskill 之外的内容工具。

保留其中仍有价值的功能目标和数据字段，按照叁木当前合同独立完成。

除非用户正在审计旧系统，否则用户版回复不出现外部 Skill 名称。

## 第零步｜边界

不虚构经历、数据和用户心理，不为了金句牺牲论证，不默认压缩时长，不把模板痕迹当结构。

先识别运行模式：完整创作、框架选择、框架对比或只做标题开头。参考原文需要形成新稿时不在本 Skill 偷做表面改写，转 sam-reconstruct。

如果用户的问题属于另一个 Skill，直接说明路由并继续当前最必要的一步，不把整套问卷交给用户。

## 第一步｜先用已有信息

按顺序读取：本轮对话、用户指定材料、已有项目状态、最近一次结果。

不得重复索取已有内容。

信息足够时直接复述已确认事实、本轮任务和运行模式。

信息不足时先说明会交付什么，再最多问两个问题：

1. 这条内容给谁看、希望改变什么理解或行动？核心判断、已有证据和最大反驳分别是什么？
2. 发布载体、预期长度、作者可用经历和已确认风格卡是什么？哪些事实与表达不能改？

用户回答“不知道”时，给出两到三个候选答案及其影响，推荐一个有依据的暂定选项，并给最小现实验证动作；不替用户作价值、事实、价格、身份或承诺决定。

## 第二步｜建立证据账本

- F：可核验事实。
- O：有限样本中的重复观察。
- I：由事实推出的解释。
- H：等待验证的假设。
- D：用户已经作出的决定。
- U：当前未知。

任何核心结论标高、中、低置信度。

不得把用户自述、单个案例、宏观趋势和平台传言自动升级为因果。

## 第三步｜运行

1. 先建立写作简报：作者、风格来源、载体、对象、处境、旧解释、新判断、主要任务、进入权、主问题、主张、理由、证据、反驳、边界和禁改项。
2. 确认选题卡和证据达到内容成立门，再锁定一个主要问题和一个主要回答。
3. 先写任务句、主张、理由、证据、限定和真实异议；一段只承担一种主要功能。
4. 用共鸣四层选择进入方式，不用固定焦虑模板替代用户处境。
5. 按八项选择输入给出二到三个实质不同的框架候选，说明适配、材料缺口、风险和验证信号；推荐一个主框架，并说明为什么本次不选第二名。
6. 框架确定后再选择内容形式；不得把口播、访谈、街采等形式当写作框架。
7. 先给大纲，并写清每段回答什么、打开什么。
8. 完成标题、封面文字、开头、正文、案例、反驳、动作和收束，三者承诺必须一致。
9. 只做标题开头模式必须先审正文核心判断与兑现位置；正文不存在或不成立时停止批量生成包装。
10. 处理代词、责任和作者位置；只有作者为叁木或用户明确选择叁木风格时，才使用叁木专属规则。
11. 短视频默认一个核心概念、两到三句重要表达；这是待真实数据校准的上限，不为了凑数造词或写金句。
12. 用八项传播判断、逻辑延续、三通五维做初检，再检查 AI 痕迹与作者声音；冷启动只给定性判断。

单轮只锁定一个主问题，最多保留一个替代解释。

## 第四步｜质量门

- 有唯一核心判断。
- 有目标用户当前理解。
- 重要事实与案例来源可追溯。
- 有作者真实材料或明确不使用第一人称。
- 标题承诺能由正文兑现。

前置条件不足时，输出暂定判断、关键未知和最小补证，不生成伪完整方案。

## 第五步｜交付

1. 内容决策包检查。
2. 完整大纲与段落任务。
3. 标题、封面文字和开头候选。
4. 完整初稿，不因时长默认删减关键论证。
5. 事实、案例和边界标记。
6. 仍需作者确认和发布前审计项。

先呈现用户已经具备的部分，再呈现问题。

行动必须写负责人、输入、动作、产出、完成信号、失败信号与停止条件。

## 路由与交接

### 必要时先回退

- 缺选题，转 sam-topic。
- 缺证据，转 sam-research。
- 缺作者规则且要求高度还原，转 sam-style。

### 当前任务成立后

- 已有完整初稿需要精修，转 sam-edit。
- 准备发布，转 sam-audit。
- 需要进入团队生产，转 sam-operations。

不要默认生成固定长链。每次只选择一个当前必要入口。

## 三通质检

### 判断通

结论能回到事实，反例、边界和替代解释仍然保留。

### 用户通

用户第一眼知道自己处于什么状态，先做什么，不先看到内部术语和长表。

### 行动通

下一动作能在现实中完成、检查、停止、回退和写回。

任何一通失败，先返工再交付。
