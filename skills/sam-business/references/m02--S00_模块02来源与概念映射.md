# 模块 02 来源与概念映射

## 一、本模块真正要解决什么

本模块不负责预测下一个风口。

它负责把“这个行业很火”“用户有痛点”“别人赚到钱了”拆成可以检查的商业条件。

最终必须回答四个问题：

1. 谁在什么处境中，需要完成什么任务。
2. 这个需要是否已经形成有效需求。
3. 价值怎样经过平台、渠道、竞争与商业模式变成交易。
4. 叁木或用户凭什么有机会进入，而不是只看见市场很大。

## 三、外部理论如何进入叁木系统

| 来源 | 支持的关系 | 不能支持的结论 |
|---|---|---|
| 科特勒、阿姆斯特朗《营销原理》 | 需要、欲望、有效需求与市场选择必须区分 | 不能据此判断某个具体账号一定有需求 |
| 波特产业结构分析 | 行业利润受到多类竞争力量共同分配 | 五力不能替代个人进入条件和平台变化 |
| Osterwalder 商业环境扫描 | 市场、行业、趋势、宏观环境要连接商业模式组件 | 扫描环境不等于完成商业模式验证 |
| Rogers 创新扩散 | 新观念通过渠道、时间和社会系统扩散，不同采用者风险判断不同 | 不能把五类采用者机械套到每个账号 |
| Moore《跨越鸿沟》 | 新产品早期市场和主流市场需要不同证据与任务 | 不适用于所有成熟品类和所有内容增长 |
| Hopkins《科学的广告》 | 冷启动优先连接既有需求，降低教育成本 | 不能推出“永远不能创造新品类” |
| OECD 平台经济研究 | 平台具有多边关系、网络效应、低边际复制成本和反馈循环 | 不能外推某个平台的具体推荐权重 |
| 叁木四项目 | 同一内容能力进入不同交易系统，结果和上限不同 | 不能证明所有行业均适用，也不能把后端结果全归因于内容 |

## 四、必须修正的历史表达

### 1. “人的欲望无限，所以市场无限”

保留：欲望是发现需求的入口。

修正：没有支付能力、支付意愿、购买时机、可达渠道和可信方案，欲望不会自动形成有效市场。

### 2. “市场来自需求”

保留：赛道名称不是市场本身。

补充：市场还需要一组愿意交换、能够交换并可被服务的参与者。

### 3. “赛道决定商业上限”

保留：付款者、客单价、复购、交付和利润结构确实受行业影响。

修正：赛道只提供约束，不直接决定个人结果。进入方式、细分任务、资源、能力和商业模式会改变可得机会。

### 4. “流量业务与 IP 业务完全不同”

保留：广告、线索、交易、订阅和到店使用不同结果指标。

修正：它们可以同时存在于同一媒体系统，必须按付款者和交易机制分账判断，不能只贴一种身份标签。

### 5. 固定平台阈值

以下内容不进入本模块事实层：

- 固定初始流量池。
- 全平台通用完播阈值。
- 永久账号权重等级。
- 单一指标决定推荐。

平台规则进入模块 07，并按官方页面和日期核验。

## 六、来源冲突处理

当书籍、项目经验和平台现状冲突时，按以下顺序处理：

1. 先确认是不是在回答同一个问题。
2. 平台事实以对应平台、对应日期的官方资料为准。
3. 交易结果以后台、订单、合同和交付记录为准。
4. 经典理论只解释关系，不覆盖实时事实。
5. 一手经验只能支持“在这些条件下发生过”。
6. 无法核验时标记假设，不补成确定结论。
