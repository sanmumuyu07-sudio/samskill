# 模块 02 跨模块边界与调用规则

## 一、本模块负责什么

模块 02 负责判断：

- 需求是否形成市场证据。
- 行业、赛道、品类和平台是否分清。
- 总市场是否转成当前可得机会。
- 行业阶段和时机怎样改变内容任务。
- 供需与竞争怎样影响获客成本。
- 商业模式怎样分配成本、收益、风险和控制权。
- 线上增长怎样连接现实业务。

## 二、本模块不负责什么

### 不负责个人资产

“我凭什么进入”需要转模块 03。

本模块只判断机会门，不替用户证明能力。

### 不负责产品设计

需求成立以后，产品承诺、价格和产品阶梯转模块 04。

### 不负责完整用户研究

用户任务、身份、决策和风险转模块 05。

### 不负责定位文档

行业和赛道是约束，公共角色与账号承诺转模块 06。

### 不负责平台细则

平台选择、分发、指标和合规转模块 07。

### 不负责销售交付

发现转化和交付断点后，转模块 15。

## 三、新用户入口

### 用户只有“想做一个热门赛道”

调用：`SAM-MKT-001` + `T01`。

输入不足时只输出需求研究清单。

### 用户已有业务，想通过线上增长

调用：`SAM-MKT-007` + `SAM-MKT-011` + `T04`。

### 用户已有账号，流量或成交下降

先分层：

- 行业和时机变化：模块 02。
- 平台分发异常：模块 07、14。
- 内容质量：模块 09—12。
- 销售交付：模块 15。

### 用户想判断风口

调用：`SAM-MKT-008` + `T03`。

不提供确定性预测。

## 四、缺少输入时怎样降级

| 缺少内容 | 降级输出 |
|---|---|
| 没有用户材料 | 给访谈、搜索、评论与替代研究清单 |
| 没有交易数据 | 只给需求与行为假设，不给利润结论 |
| 没有成本 | 不判断商业可行性，只列待补台账 |
| 没有平台官方资料 | 标记时效未知，转模块 07 核验 |
| 没有个人能力证据 | 标记市场存在、个人入口未知，转模块 03 |

## 五、停止条件

出现以下任一情况，停止继续做增长方案：

- 产品涉及未解决的资质或合规风险。
- 内容承诺明显超过交付。
- 用户和付款者无法识别。
- 关键交易数据被不同业务混算。
- 需要大规模不可逆投入，核心假设尚无行为证据。
- 用户没有现实任务，只想获得创业身份认同。

## 六、模块输出格式

每次完整诊断必须交付：

1. 当前决策问题。
2. 已知事实、推断、未知和假设。
3. 市场证据等级。
4. 个人机会五道门。
5. 主交易模型与结构性上限。
6. 当前内容应该承担的任务。
7. 最小验证动作。
8. 继续与停止条件。
9. 下一模块。

## 七、Skill 调用链

```text
用户问题
→ 判断是否属于市场／行业／商业环境
→ 收集 T01 最小输入
→ 若环境复杂，再调用 T02
→ 涉及时机，调用 T03
→ 涉及交易与后端，调用 T04
→ 输出第一断点与下一模块
→ 将验证结果写回模块 14
```

不得一次调用全部工具制造“完整感”。

只调用当前决策需要的最短链。
