# 交易模型与成本收益风险台账

## 使用目的

判断流量、线索、成交和交付分别由谁完成，价值最终留在哪里。

## 第一步｜参与者

逐一列出：

- 观看者。
- 使用者。
- 决策者。
- 付款者。
- 平台。
- 渠道或机构。
- 内容与销售团队。
- 产品与交付团队。
- 供应商和合作方。

任何实际参与者不得省略。

## 第二步｜六流台账

| 流 | 从谁到谁 | 发生什么 | 证据 |
|---|---|---|---|
| 用户流 |  | 发现、筛选、成交、服务 |  |
| 价值流 |  | 谁提供什么结果 |  |
| 资金流 |  | 付款、分成、回款 |  |
| 成本流 |  | 获客、销售、履约、售后 |  |
| 风险流 |  | 平台、合规、库存、退款 |  |
| 决策流 |  | 谁能改价格、产品、渠道 |  |

## 第三步｜统一金额口径

```text
甲方或用户总支付：
平台／渠道／机构扣除：
实收：
直接成本：
毛利：
获客与销售：
交付与售后：
固定成本：
退款与坏账：
净结果：
创始人工时：
回款周期：
```

无法核验的数字标“自述待补证”。

## 第四步｜交易模型分类

- 广告与品牌预算。
- 线索与服务成交。
- 商品与电商。
- 订阅与会员。
- 到店与本地服务。
- 平台分成。
- 混合模式。

混合模式分别记账。

## 第五步｜结构性上限

按顺序检查：

1. 用户上限。
2. 渠道上限。
3. 信任与销售上限。
4. 产品与交付上限。
5. 利润与现金流上限。
6. 决策权上限。

第一处阻止结果继续增长的节点，定义为当前结构性上限。

## 第六步｜内容职责

内容可以承担：

- 被发现。
- 被理解。
- 被信任。
- 资格筛选。
- 行动提示。
- 结果公开与反馈回流。

内容不能单独承担：

- 供应链修改。
- 销售谈判全部责任。
- 产品交付。
- 合同和资质。
- 真实利润。

## 标准输出

```text
主交易模型：
次交易模型：
付款者／使用者／受益者：
核心资产：
收入与成本口径：
主要风险：
当前结构性上限：
内容能修复：
内容不能修复：
负责决策的人：
未来一轮验证：
停止扩量条件：
```

## 使用边界

本台账不替代财务、会计、税务和法律审计。

它用于避免内容团队越权归因和商业结果混算。
