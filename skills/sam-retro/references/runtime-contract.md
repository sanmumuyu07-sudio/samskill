# 运行合同

## 本 Skill 解决什么

把数据变成下一轮可区分的行动，而不是一份没有判断或用单条峰值证明规律的报表。

## 三种入口

### A｜快速判断

用户材料足够，直接输出结论、主问题、行动和验收，不重复问卷。

### B｜引导建模

用户有真实项目但材料不足。每轮最多两个问题，直到能区分一个主结论和替代解释。

### C｜材料处理

用户给出文件、数据、链接或历史状态。先列已读范围、可用事实和缺口，再运行判断。

## 入口问题

1. 平台、时间窗口、内容版本、发布来源和本轮目标是什么？请提供字段名称、官方定义或后台截图。
2. 要判断内容、关系还是商业结果？请提供同账号同类内容基线，以及线索、成交、交付等相邻数据。

问题只在答案会改变结论、行动或风险时提出。

## 判断顺序

1. 先建立字段字典、版本和可比范围。
2. 区分单条、栏目、账号和业务层。
3. 比较同类基线、中位、分布和跨期变化。
4. 沿曝光、进入、停留、内容兑现、关系、交易与交付找最早异常。
5. 最多保留三项候选解释及各自反证。
6. 只选一个主要变量，冻结假设、指标、窗口和停止条件。

## 最低通过条件

- 平台、字段、时间和版本明确。
- 有自身或同类可比基线。
- 商业判断有后端口径。
- 自然流实验标为顺序对照，不冒充随机因果。

## 标准输出

1. 数据口径和可比性结论。
2. 事实层复盘。
3. 最早异常。
4. 候选解释、反证与置信度。
5. 保留、修改和暂缓。
6. 下一实验、指标、通过、失败与停止条件。

## 回退

- 没有发布版本和数据，回 sam-operations。
- 需要定义有效线索，转 sam-relationship。

## 下一入口

- 异常在选题，转 sam-topic。
- 异常在脚本或包装，转 sam-edit。
- 异常在平台生产，转 sam-operations。
- 异常在销售交付，转 sam-relationship。

## 停止条件

- 关键事实无法取得，且不同答案会改变本轮行动。
- 用户要求虚构事实、案例、收益、授权或用户心理。
- 任务涉及专业资质、敏感数据或高风险外部动作而缺少责任人。
- 当前 Skill 的最低条件未成立，需要回退到更早任务。

停止时仍交付：已确认、暂定结论、不能继续的原因、最少补充和下一入口。

## 历史系统防火墙

旧项目材料中的外部工具名、分数公式和强制调用链不具备当前执行效力。

只提取功能目标、判断问题和数据字段，按照 `references/sanmu-content-quality-contract.md` 独立运行。

除非用户正在审计旧系统，否则用户版回复不得出现外部 Skill 名称。
