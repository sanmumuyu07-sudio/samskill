# 叁木内容框架选择器 V2.2

## 这份规则解决什么

内容框架不是作者风格，也不是视频形式。

它是观众完成一次理解任务时，信息应当怎样推进。

同一个作者可以使用不同框架；同一个框架也可以写成口播、访谈、图文或长文。

禁止先套模板再寻找观点。先确定内容任务、目标用户当前状态、材料与作者进入权，再选择框架。

## 选择输入

每次至少判断八项：

1. **内容任务**：获得注意、理解问题、相信判断、比较选择、开始行动，还是完成交付。
2. **用户状态**：不知道问题、知道问题但解释错误、知道答案但不相信、相信但不会做、准备购买或反对。
3. **材料类型**：事实、研究、案例、亲历、用户原话、过程记录、产品机制或结果数据。
4. **作者进入权**：亲历者、操盘者、研究者、服务者、观察者或仅有二手材料。
5. **赛道条件**：风险、决策周期、专业门槛、用户是否需要资质与结果证明。
6. **商业距离**：纯公共表达、建立认知、建立信任、连接线索、解释产品或处理异议。
7. **载体容量**：短口播、长口播、图文、长文、访谈、屏幕演示等。
8. **风险与边界**：事实时效、隐私、版权、未成年人、医疗金融法律、结果承诺与平台规则。

## 选择流程

1. 先写一句任务句：让【谁】从【当前理解】走到【新的判断或行动】。
2. 排除材料无法支撑、作者没有进入权或风险不可接受的框架。
3. 给出二到三个实质不同的候选框架。
4. 每个候选说明：为什么适合、缺什么材料、最大风险、验证信号。
5. 推荐一个主框架，并说明为什么本次不选第二名。
6. 用户明确指定其他框架时可以改选，但不得绕过证据和风险门。

信息充分且只有一个合理选项时直接选择，不为了展示过程制造菜单。

## 框架库

### F01｜反共识纠偏

- **任务**：纠正一个广泛使用但在特定条件下失效的解释。
- **适合**：用户已认识问题，却把原因归错；作者有反例、机制或实践证据。
- **推进**：明确旧说法 → 承认它何时有效 → 指出失效条件 → 给替代解释 → 给判断或动作。
- **不适合**：只有不同态度，没有新增事实；靠“所有人都错了”制造冲突。
- **失败信号**：评论只争立场，无法复述新解释；正文没有承担更高举证责任。
- **验证**：目标用户能说清旧解释在哪些条件下不够，以及新的判断如何改变行动。

### F02｜时代处境解释

- **任务**：把个人困惑放回技术、制度、文化、行业或资源变化中理解。
- **适合**：个人 IP、一人公司、职业焦虑、行业变化、身份与机会问题。
- **推进**：共同现象 → 时代变化 → 旧适应方式为何失效 → 个体处境 → 新机会与代价 → 现实任务。
- **不适合**：用宏大趋势掩盖个人证据不足；把相关性写成必然因果。
- **失败信号**：读者只感到“时代如此”，却不知道自己能检查什么、做什么。
- **验证**：用户能把个人问题与一个具体外部变化连接，并识别自己的可控部分。

### F03｜问题诊断

- **任务**：把模糊失败拆成最早断点，而不是直接给万能方案。
- **适合**：低播放、高流量低咨询、有咨询不成交、团队产能不稳等。
- **推进**：结果口径 → 完整链路 → 已成立节点 → 最早异常 → 候选解释与反证 → 下一检查。
- **不适合**：没有相邻数据却要做确定归因；把评分当诊断。
- **失败信号**：列出十个问题但没有先后；建议无法验证。
- **验证**：用户知道先补哪个字段、只改哪个变量、何时停止。

### F04｜因果与机制解释

- **任务**：解释一个结果通过什么中间关系发生。
- **适合**：算法、用户决策、传播、内容获客、产品机制与商业模式。
- **推进**：现象 → 条件 → 动作 → 中间反应 → 结果 → 替代解释 → 边界。
- **不适合**：只有相关数据；把类比当机制证明。
- **失败信号**：从动作直接跳结果；用户知道“是什么”却不知道“为什么”。
- **验证**：更换表面形式后，用户仍能指出应被保留的关系。

### F05｜案例拆解

- **任务**：从具体案例提取可迁移关系和不可迁移条件。
- **适合**：账号、商业模式、内容形式、项目复盘与竞争案例。
- **推进**：研究问题 → 已知事实 → 成立条件 → 动作与机制 → 结果口径 → 替代解释 → 迁移实验。
- **不适合**：单条爆款、只看成功样本、公开材料推断利润后台。
- **失败信号**：结论是抄标题、镜头、人设或话术。
- **验证**：输出能进入本项目的一次最小实验，而不是停在“学到了”。

### F06｜个人经验复盘

- **任务**：把亲历从故事变成可检查的经验边界。
- **适合**：操盘、创业、职业、项目失败、方法形成过程。
- **推进**：当时条件 → 目标 → 做法 → 结果 → 本人贡献与外部条件 → 错误归因 → 现在的判断。
- **不适合**：把组织结果全归个人；用结果替代方法。
- **失败信号**：只剩成功叙事或情绪忏悔，不能指导下一次判断。
- **验证**：读者能区分可复制动作、必要条件和偶然因素。

### F07｜故事转折

- **任务**：让抽象判断通过人物选择与后果被看见。
- **适合**：高情绪经历、用户案例、价值观冲突、身份变化。
- **推进**：处境 → 目标 → 阻力 → 关键选择 → 后果 → 重新理解 → 回到公共判断。
- **不适合**：没有真实材料；为了反转篡改时间线；故事与主张没有关系。
- **失败信号**：故事好看但无法说出内容在证明什么。
- **验证**：去掉煽情词，人物选择仍能支撑核心判断。

### F08｜趋势解释

- **任务**：判断变化是热点、周期、结构趋势还是尚未确认的信号。
- **适合**：平台变化、AI、自媒体、行业机会、消费与职业变化。
- **推进**：变化事实 → 时间与范围 → 推动因素 → 受益受损者 → 反向证据 → 对当前项目的动作。
- **不适合**：把新闻当趋势；用未来叙事制造紧迫销售。
- **失败信号**：只有“时代红利”，没有时间窗口、条件和风险。
- **验证**：用户知道哪些变量要持续观察，什么信号会推翻判断。

### F09｜对比决策

- **任务**：帮助用户在两个或多个方案之间做条件化选择。
- **适合**：平台、产品、价格、内容形式、服务方案、职业路径。
- **推进**：同一决策任务 → 共同维度 → 条件差异 → 成本收益风险 → 适合谁 → 不适合谁 → 最小选择。
- **不适合**：比较对象口径不同；预先站队后拼优缺点。
- **失败信号**：每个选项都“各有优势”，用户仍不会选。
- **验证**：用户能用自己的条件排除一个选项，并知道代价。

### F10｜教程交付

- **任务**：让用户完成一个可检查动作。
- **适合**：选题、拍摄、研究、数据、工具、流程和业务操作。
- **推进**：完成结果 → 前置条件 → 步骤 → 每步产物 → 常见错误 → 验收 → 失败回退。
- **不适合**：目标本身未成立；需要判断却只给步骤。
- **失败信号**：步骤看似详细，却没有输入、输出和完成信号。
- **验证**：陌生用户能独立做完，并留下可供下一环节使用的产物。

### F11｜用户问答

- **任务**：直接消解一个真实疑问，而不是借问题自说自话。
- **适合**：评论回复、搜索问答、产品异议、专业解释。
- **推进**：复述问题与隐含前提 → 直接回答 → 分条件解释 → 例子 → 边界 → 下一判断。
- **不适合**：问题是虚构的；借个别问题代表整个群体。
- **失败信号**：回答了一个更容易的问题；结论需大量作者背景才能理解。
- **验证**：提问者能判断自己的条件属于哪个分支。

### F12｜产品与商业机制解释

- **任务**：解释产品解决什么任务、通过什么交付、为何值这个价格和有什么边界。
- **适合**：知识库、社群、课程、咨询、专业服务与实体产品。
- **推进**：目标用户任务 → 现有替代方案 → 产品机制 → 交付与证据 → 成本与价格 → 不适合人群 → 行动入口。
- **不适合**：产品尚未定义；用情绪内容突然硬转销售。
- **失败信号**：只列功能或赠品；结果承诺超过交付控制范围。
- **验证**：用户能说清自己为什么需要、会得到什么、仍需承担什么。

### F13｜异议处理

- **任务**：处理妨碍理解、信任或行动的最强合理异议。
- **适合**：价格、风险、适用性、证据、时间、能力和替代方案问题。
- **推进**：准确复述异议 → 承认合理部分 → 区分条件 → 提供证据 → 说明不可解决部分 → 给选择。
- **不适合**：把批评者贬成认知低；用话术回避真实缺陷。
- **失败信号**：只是在“反驳用户”；没有改变风险结构。
- **验证**：即使不购买，用户也能得到更准确的判断。

### F14｜证据证明

- **任务**：让一个重要判断接受材料、反例和边界检验。
- **适合**：高专业、高风险、反直觉、结果型或公共事实内容。
- **推进**：待证明主张 → 证据角色 → 推理连接 → 反例 → 限定 → 当前结论强度。
- **不适合**：材料不可追溯；用权威名言替代事实。
- **失败信号**：数据很多但没有回答同一个质疑。
- **验证**：读者知道证据支持什么、不能支持什么。

### F15｜热点借势

- **任务**：用当下事件解释账号长期命题，而不是消费热点本身。
- **适合**：事件与目标用户、作者进入权、长期问题有真实连接。
- **推进**：已确认事件 → 用户为何在意 → 常见解释 → 作者长期判断 → 新证据或应用 → 时效边界。
- **不适合**：事实未核；只能表态；与账号任务无关。
- **失败信号**：热点过去后内容没有任何独立价值。
- **验证**：去掉人物或事件名，核心机制仍对目标用户有用。

### F16｜身份与群体处境

- **任务**：把分散经验组织成可识别语言，并连接现实任务。
- **适合**：共同处境、职业身份、代际经验、创业与表达困境。
- **推进**：具体处境 → 重复冲突 → 用户原话 → 身份期待与风险 → 新命名或解释 → 需要承担的行动。
- **不适合**：身份预支、优越感、羞耻动员、用单一评论代表群体。
- **失败信号**：用户只得到“我就是这类人”的安慰，没有现实任务。
- **验证**：既有“被理解”，也能指出下一项责任或行动。

### F17｜过程记录与实验

- **任务**：公开一次正在发生的实践，让方法通过过程获得证据。
- **适合**：冷启动、挑战、产品研发、账号迭代、学习与团队实验。
- **推进**：问题与基线 → 假设 → 动作 → 过程证据 → 结果 → 异常 → 下一轮。
- **不适合**：事后伪装实时；一次结果包装成规律。
- **失败信号**：只报结果，不保留失败和版本。
- **验证**：观众能检查过程，项目能把结果写回规则。

### F18｜清单与盘点

- **任务**：降低检索和执行成本，帮助用户快速查缺补漏。
- **适合**：工具、风险项、流程节点、材料准备和复盘检查。
- **推进**：清单用途 → 分类依据 → 项目 → 使用顺序 → 致命项 → 完成标准。
- **不适合**：需要因果解释或价值判断；为了数量堆常识。
- **失败信号**：任意一项可被替换，分类没有决策价值。
- **验证**：用户能用清单做检查并找到一个明确缺口。

## 组合规则

一条内容只设一个主框架，最多使用一个辅助框架。

常见组合：

- 反共识纠偏 + 证据证明。
- 时代处境解释 + 身份与群体处境。
- 案例拆解 + 因果与机制解释。
- 问题诊断 + 教程交付。
- 产品机制解释 + 异议处理。
- 过程记录 + 个人经验复盘。

禁止为了“丰富”把多个框架并列堆在一条短内容里。

## 底层来源

本选择器吸收而不照搬：金字塔原理的信息组织、图尔敏论证、PAS/AIDA 等常见说服结构、框架理论、叙事运输、精细加工可能性模型、使用与满足、广告相关性与承诺兑现、条件—机制—结果、类比迁移，以及叁木模块 08—12 的对标、包装、论证与传播原子。

框架名称是工作标签，不宣称为独创理论。叁木的独立部分是：以现实任务、证据、作者进入权、商业距离和反馈结果共同决定框架，并把版本写回项目资产。
