# 运行合同

## 本 Skill 解决什么

让前端内容与后端结果使用同一条可追踪链路，并优先修复最早出现的关系、适配、承诺或交付断点。

## 三种入口

### A｜快速判断

用户材料足够，直接输出结论、主问题、行动和验收，不重复问卷。

### B｜引导建模

用户有真实项目但材料不足。每轮最多两个问题，直到能区分一个主结论和替代解释。

### C｜材料处理

用户给出文件、数据、链接或历史状态。先列已读范围、可用事实和缺口，再运行判断。

## 入口问题

1. 本轮要获得咨询、成交、合作还是职业机会？请定义有效结果，并提供过去30—90天各层数量和来源。
2. 目标用户从内容到下一步经过什么入口？产品、价格、销售、交付、退款和复购分别是什么实际情况？

问题只在答案会改变结论、行动或风险时提出。

## 判断顺序

1. 定义目标链和L0—L7或非交易关系状态。
2. 按来源内容追踪主页、行动、线索、适配、咨询和结果。
3. 检查任务、时机、预算、决策、资源、产品适配与风险。
4. 区分内容筛选、入口、产品、销售、承诺和交付问题。
5. 锁定最早断点与一个替代解释。
6. 设计分流、修复、隐私和回填动作。

## 最低通过条件

- 有效线索或有效关系有明确定义。
- 数据按产品、来源和时间分组。
- 销售与交付口径可区分。
- 涉及客户隐私时只使用最小必要字段。

## 标准输出

1. 目标结果链与当前阶段。
2. 来源内容到结果的漏斗。
3. 有效线索和适配标准。
4. 最早断点与替代解释。
5. 销售、承诺、交付和容量风险。
6. 七天修复与回填、停止和转介条件。

## 回退

- 产品本身不清，转 sam-product。
- 只有播放数据没有后端链路，先转 sam-retro 补口径。

## 下一入口

- 前端内容吸引错人，转 sam-position 或 sam-topic。
- 发现数据异常，转 sam-retro。
- 交付规则与团队需要资产化，转 sam-assets。

## 停止条件

- 关键事实无法取得，且不同答案会改变本轮行动。
- 用户要求虚构事实、案例、收益、授权或用户心理。
- 任务涉及专业资质、敏感数据或高风险外部动作而缺少责任人。
- 当前 Skill 的最低条件未成立，需要回退到更早任务。

停止时仍交付：已确认、暂定结论、不能继续的原因、最少补充和下一入口。
