# 叁木｜关系、线索与交付

## 交付目标

让前端内容与后端结果使用同一条可追踪链路，并优先修复最早出现的关系、适配、承诺或交付断点。

用户离开本 Skill 时必须知道：当前结论、判断依据、只先做什么、怎样验收、失败时回哪里、下一任务是什么。

## 必读与按需资料

启动后先完整读取 `references/sanmu-intake-and-delivery-contract.md` 与 `references/public-io.md`，先确定本轮任务、交付对象、输出深度和五类信息状态。

随后读取：

1. `references/runtime-contract.md`：入口、判断顺序和结束条件。
2. `references/output-contract.md`：用户版交付、状态和交接。
3. `references/method-index.md`：根据当前断点选择原子库运行包、工具和案例。
4. `references/family-and-multi-role-decision-atom.md`：观看、使用、付款、批准、签约和评价角色不一致时完整读取。

需要追溯理论、版本或原创性时读取 `references/source-map.md`。

需要测试边界时读取 `references/pressure-tests.md` 与 `evals/evals.json`。

只加载当前任务所需资料，不一次读完全部 references。

追问、暂定判断、阻断确认、正式方案和状态交接必须遵守共用输入与交付协议。不要把内部推理、Skill 名或原子编号写进客户正式方案。

## 第零步｜边界

不把私信都算有效线索，不用销售掩盖产品和交付问题，不把所有互动强行销售化，不保存不必要的隐私数据。

如果用户的问题属于另一个 Skill，直接说明路由并继续当前最必要的一步，不把整套问卷交给用户。

## 第一步｜先用已有信息

按顺序读取：本轮对话、用户指定材料、已有项目状态、最近一次结果。

不得重复索取已有内容。

信息足够时直接复述已确认事实、本轮任务和运行模式。

信息不足时先说明会交付什么，再最多问两个问题：

1. 本轮要获得咨询、成交、合作还是职业机会？请定义有效结果，并提供过去30—90天各层数量和来源。
2. 目标用户从内容到下一步经过什么入口？产品、价格、销售、交付、退款和复购分别是什么实际情况？

用户回答“不知道”时，给出两到三个候选答案及其影响，推荐一个有依据的暂定选项，并给最小现实验证动作；不替用户作价值、事实、价格、身份或承诺决定。

## 第二步｜建立证据账本

- F：可核验事实。
- O：有限样本中的重复观察。
- I：由事实推出的解释。
- H：等待验证的假设。
- D：用户已经作出的决定。
- U：当前未知。

任何核心结论标高、中、低置信度。

不得把用户自述、单个案例、宏观趋势和平台传言自动升级为因果。

## 第三步｜运行

1. 定义目标链和L0—L7或非交易关系状态。
2. 按来源内容追踪观看者到问题承担者、使用者、付款者、批准者、签约者和评价者之间的实际转换。
3. 检查谁被内容触达、谁愿意继续、谁承担预算、谁拥有否决权、谁最终确认结果。
4. 检查任务、时机、预算、决策、资源、产品适配与风险。
5. 区分内容筛选、入口、角色错位、产品、销售、承诺和交付问题。
6. 锁定最早断点与一个替代解释。
7. 设计分流、修复、授权、隐私和回填动作。

单轮只锁定一个主问题，最多保留一个替代解释。

## 第四步｜质量门

- 有效线索或有效关系有明确定义。
- 数据按产品、来源和时间分组。
- 销售与交付口径可区分。
- 涉及客户隐私时只使用最小必要字段。

前置条件不足时，输出暂定判断、关键未知和最小补证，不生成伪完整方案。

## 第五步｜交付

1. 目标结果链与当前阶段。
2. 来源内容到结果的漏斗。
3. 有效线索和适配标准。
4. 最早断点与替代解释。
5. 销售、承诺、交付和容量风险。
6. 七天修复与回填、停止和转介条件。

先呈现用户已经具备的部分，再呈现问题。

行动必须写负责人、输入、动作、产出、完成信号、失败信号与停止条件。

## 路由与交接

### 必要时先回退

- 产品本身不清，转 sam-product。
- 只有播放数据没有后端链路，先转 sam-retro 补口径。

### 当前任务成立后

- 前端内容吸引错人，转 sam-position 或 sam-topic。
- 发现数据异常，转 sam-retro。
- 交付规则与团队需要资产化，转 sam-assets。

不要默认生成固定长链。每次只选择一个当前必要入口。

## 状态字段

本轮至少保存：

- `result_type`
- `lead_source`
- `lead_stage`
- `qualification`
- `fit_status`
- `decision_roles`
- `role_transitions`
- `role_conflicts`
- `final_confirmer`
- `authorization_status`
- `offer`
- `promise_version`
- `delivery_status`
- `refund_status`
- `repeat_task`
- `capacity`
- `privacy_scope`
- `next_action`

同时保存 `intake`：交付对象、交付形态、已确认、暂定、有歧义、相互冲突、未知、必须确认、非阻断未知和受影响章节。

同时生成 `handoff`：来源 Skill、当前任务、已确认输入、暂定判断、冲突、关键未知、权限边界、不得破坏、下一入口、所需输入和完成信号。

未经明确授权只输出预览，不写入用户项目，不发布，不联系客户，不收款，不覆盖真源。

## 三通质检

### 判断通

结论能回到事实，反例、边界和替代解释仍然保留。

### 用户通

用户第一眼知道自己处于什么状态，先做什么，不先看到内部术语和长表。

### 行动通

下一动作能在现实中完成、检查、停止、回退和写回。

任何一通失败，先返工再交付。
