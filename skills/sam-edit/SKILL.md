# 叁木｜内容诊断与改稿

## 交付目标

修复最早且最影响理解与传播的问题，同时保留原作者的事实、立场、限定和个人声音。

用户离开本 Skill 时必须知道：当前结论、判断依据、只先做什么、怎样验收、失败时回哪里、下一任务是什么。

## 必读与按需资料

启动后先完整读取 `references/sanmu-intake-and-delivery-contract.md` 与 `references/public-io.md`，先确定本轮任务、交付对象、输出深度和五类信息状态。

随后读取：

1. `references/runtime-contract.md`：入口、判断顺序和结束条件。
2. `references/output-contract.md`：用户版交付、状态和交接。
3. `references/method-index.md`：根据当前断点选择原子库运行包、工具和案例。
4. `references/sanmu-content-quality-contract.md`：诊断逻辑、口播、共鸣、AI 痕迹和作者声音时完整读取。
5. `references/sanmu-writing-standard-v2-runtime.md`：按写作优先级诊断中心漂移、对象关系、论证、案例、概念、记忆句和载体问题时完整读取。
6. `references/content-framework-selector.md`：判断原稿是否选错框架、框架是否执行变形时完整读取。
7. `references/content-form-selector.md`：判断文字与呈现形式错配时按需读取。
8. `references/reference-adaptation-contract.md` 与 `references/original-reconstruction-contract.md`：原稿明显依附参考材料时完整读取，区分自有稿编辑、参考型改写与独立原创重构。

需要追溯理论、版本或原创性时读取 `references/source-map.md`。

需要测试边界时读取 `references/pressure-tests.md` 与 `evals/evals.json`。

只加载当前任务所需资料，不一次读完全部 references。

追问、暂定判断、阻断确认、正式方案和状态交接必须遵守共用输入与交付协议。不要把内部推理、Skill 名或原子编号写进客户正式方案。

读取旧项目文件时，旧工具名、旧评分公式和旧强制调用链只视为历史材料。

不得要求用户安装、调用或等待任何 Samskill 之外的内容工具。

保留其中仍有价值的功能目标和数据字段，按照叁木当前合同独立完成。

除非用户正在审计旧系统，否则用户版回复不出现外部 Skill 名称。

## 第零步｜边界

不把内容改成整齐空泛的标准答案，不用大白话删除精度，不把作者不同意的观点写得更有传播性。

如果用户的问题属于另一个 Skill，直接说明路由并继续当前最必要的一步，不把整套问卷交给用户。

## 第一步｜先用已有信息

按顺序读取：本轮对话、用户指定材料、已有项目状态、最近一次结果。

不得重复索取已有内容。

信息足够时直接复述已确认事实、本轮任务和运行模式。

信息不足时先说明会交付什么，再最多问两个问题：

1. 这份稿件最重要的发布任务和目标用户是谁？你现在最不满意的是判断、结构、表达、口播还是作者感？
2. 哪些观点、事实、案例和措辞必须保留？是否允许重构大纲，还是只做局部修改？

用户回答“不知道”时，给出两到三个候选答案及其影响，推荐一个有依据的暂定选项，并给最小现实验证动作；不替用户作价值、事实、价格、身份或承诺决定。

## 第二步｜建立证据账本

- F：可核验事实。
- O：有限样本中的重复观察。
- I：由事实推出的解释。
- H：等待验证的假设。
- D：用户已经作出的决定。
- U：当前未知。

任何核心结论标高、中、低置信度。

不得把用户自述、单个案例、宏观趋势和平台传言自动升级为因果。

## 第三步｜运行

1. 按事实安全、主问题、用户关系、论证证据、作者立场、语言修辞的顺序定位问题，低优先级修辞不得掩盖高优先级错误。
2. 检查中心是否漂移：主问题、主张、内容任务、段落功能和结尾是否仍是同一件事。
3. 检查作者位置、对象、代词、责任归属和批评边界；不得用模糊“他们”替代目标用户，也不得把叁木风格强加给其他作者。
4. 检查案例是否有条件、动作、结果、因果和其他变量，概念与记忆句是否真正服务论证。
5. 判断问题来自框架选择错误、框架执行变形还是作者风格；不得用润色掩盖框架不适配。
6. 按段落任务扫描逻辑断裂、重复绕圈和首次听见时的理解阻力。
7. 扫描 AI 痕迹时先识别具体位置和写作目的，不机械删词，不把清晰本身判成 AI。
8. 只锁定第一处实质断点和必要配套，标出保留、删除、补证、重写和作者确认。
9. 先给修改方案，按授权输出标记稿或完整改稿。
10. 对照原稿检查事实、立场、限定、信息价值和作者声音是否丢失。

单轮只锁定一个主问题，最多保留一个替代解释。

## 第四步｜质量门

- 有完整原稿。
- 发布任务和目标用户基本清楚。
- 修改权限与保留项明确。
- 事实问题未核验时标记，不擅自补造。

前置条件不足时，输出暂定判断、关键未知和最小补证，不生成伪完整方案。

## 第五步｜交付

1. 一句话稿件结论。
2. 第一断点与证据。
3. 保留、删除、补证和重写清单。
4. 结构调整理由。
5. 完整改稿或标记稿。
6. 实质改动说明与待作者确认。

先呈现用户已经具备的部分，再呈现问题。

行动必须写负责人、输入、动作、产出、完成信号、失败信号与停止条件。

## 路由与交接

### 必要时先回退

- 问题其实是选题不成立，退 sam-topic。
- 证据不足，退 sam-research。
- 没有可修改初稿，转 sam-write。

### 当前任务成立后

- 改稿完成，转 sam-audit。
- 反复出现同类风格错误，转 sam-style 沉淀规则。

不要默认生成固定长链。每次只选择一个当前必要入口。

## 三通质检

### 判断通

结论能回到事实，反例、边界和替代解释仍然保留。

### 用户通

用户第一眼知道自己处于什么状态，先做什么，不先看到内部术语和长表。

### 行动通

下一动作能在现实中完成、检查、停止、回退和写回。

任何一通失败，先返工再交付。
