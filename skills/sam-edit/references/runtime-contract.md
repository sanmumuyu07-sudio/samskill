# 运行合同

## 本 Skill 解决什么

修复最早且最影响理解与传播的问题，同时保留原作者的事实、立场、限定和个人声音。

## 三种入口

### A｜快速判断

用户材料足够，直接输出结论、主问题、行动和验收，不重复问卷。

### B｜引导建模

用户有真实项目但材料不足。每轮最多两个问题，直到能区分一个主结论和替代解释。

### C｜材料处理

用户给出文件、数据、链接或历史状态。先列已读范围、可用事实和缺口，再运行判断。

## 入口问题

1. 这份稿件最重要的发布任务和目标用户是谁？你现在最不满意的是判断、结构、表达、口播还是作者感？
2. 哪些观点、事实、案例和措辞必须保留？是否允许重构大纲，还是只做局部修改？

问题只在答案会改变结论、行动或风险时提出。

## 判断顺序

1. 先判断问题属于选题、证据、论证、结构、表达、口播还是风格。
2. 只锁定第一处实质断点和必要配套。
3. 标出保留、删除、补证、重写和作者确认。
4. 先给修改方案，说明会改变什么。
5. 按授权输出标记稿或完整改稿。
6. 对照原稿检查事实、立场、边界和声音是否丢失。

## 最低通过条件

- 有完整原稿。
- 发布任务和目标用户基本清楚。
- 修改权限与保留项明确。
- 事实问题未核验时标记，不擅自补造。

## 标准输出

1. 一句话稿件结论。
2. 第一断点与证据。
3. 保留、删除、补证和重写清单。
4. 结构调整理由。
5. 完整改稿或标记稿。
6. 实质改动说明与待作者确认。

## 回退

- 问题其实是选题不成立，退 sam-topic。
- 证据不足，退 sam-research。
- 没有可修改初稿，转 sam-write。

## 下一入口

- 改稿完成，转 sam-audit。
- 反复出现同类风格错误，转 sam-style 沉淀规则。

## 停止条件

- 关键事实无法取得，且不同答案会改变本轮行动。
- 用户要求虚构事实、案例、收益、授权或用户心理。
- 任务涉及专业资质、敏感数据或高风险外部动作而缺少责任人。
- 当前 Skill 的最低条件未成立，需要回退到更早任务。

停止时仍交付：已确认、暂定结论、不能继续的原因、最少补充和下一入口。

## 历史系统防火墙

旧项目材料中的外部工具名、分数公式和强制调用链不具备当前执行效力。

只提取功能目标、判断问题和数据字段，按照 `references/sanmu-content-quality-contract.md` 独立运行。

除非用户正在审计旧系统，否则用户版回复不得出现外部 Skill 名称。
