# 模块 11｜结构、证据与口播表达 Skill-ready 运行包

## 一、前置质量门

必须有：通过审核的选题、唯一核心主张、目标用户当前理解、已有证据和希望发生的行动。

缺主张退模块09；包装承诺错误退模块10；来源无法核查停止举证，不用语言补空白。

## 二、脚本状态

S0素材堆积；S1有主张无论证；S2论证完整但结构未通过；S3结构与口播通过；S4发布后复盘支持稳定使用。

## 四、论证五件套与证据等级

主张、根据、推理连接、成立限定、最强异议缺一不可。事实、案例、数据、引用和类比分工；类比只解释，不证明。

E0无材料；E1单一线索；E2直接来源；E3独立支持；E4正反与边界；E5可审计。核心强主张低于E2必须降级为工作假设。

## 五、工具合同

- T01 输出任务句、论证五件套、结构理由和段落任务。
- T02 每条材料写可支持／不可支持，数字写分母、时间和口径。
- T03 逐段写承上、回答、引出；本人试读修改进入风格规则候选。
- T04 第一通判断证据、第二通结构理解、第三通口播发布；前一通失败不得跳后面。

## 六、案例矩阵

| 类型 | 案例 | 支持 | 不支持 |
|---|---|---|---|
| 正向 | “个人IP先找任务而非人设”按问题—机制—证据—动作展开 | 结构服务理解任务 | 该结构适合所有内容 |
| 失败 | 只有“你不是不努力，是方向错了”反复换说法 | 强观点不等于论证 | 金句没有价值 |
| 边界 | 人物经历先讲故事再给结论 | 故事可承载判断 | 所有专业内容都应故事化 |
| 跨行业 | 商业、留学、实体案例都需拆本人贡献和条件 | 证据角色可迁移 | 同一案例证明相同结论 |
| 反例 | 类比算法像“媒婆”后直接推出权重规则 | 类比不能证明机制 | 类比不能帮助理解 |

## 七、金样本输出骨架

```text
任务句：让想做个人IP但只在找人设的人，从身份包装走到现实任务与公共证明。
主张：个人IP的起点不是人设，而是一个能被陌生人检查的现实任务。
根据：用户不会因自称相信；项目结果与能力需证据；账号承诺需长期兑现。
限定：生活方式内容也需要稳定选择，但不一定以专业任务为主。
异议：清楚人设能降低识别成本——成立，但它应当压缩真实定位，不应替代定位。
段落：时代入口→错误顺序→为什么→三项检查→七天动作。
```
