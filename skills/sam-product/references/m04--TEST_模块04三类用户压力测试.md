# 模块 04 三类用户压力测试

## 测试一｜只有经验，想直接卖课

### 用户输入

“我做了五年运营，准备录一套 99 节自媒体课程，定价 1999。”

### 错误输出

直接帮用户列课程目录、价格和销售页。

### 正确输出

1. 回模块 03 检查能力证据与归因。
2. 追问一个具体用户场景和任务。
3. 用 `T01` 定义最小结果承诺。
4. 没有付款与交付证据时，只设计小范围试点。

### 路由

模块 03 → 模块 04 → 模块 05。

## 测试二｜知识库卖得动，社群交付失控

### 用户输入

“299 元知识库送永久群，大家每天都让我看账号和改稿。”

### 错误输出

建议提价或招助教，不处理承诺问题。

### 正确输出

1. 用 `SAM-OFFER-010` 区分知识库、答疑和咨询。
2. 用 `T02` 计算单客服务成本。
3. 用 `T03` 写答疑频率、问题格式、批改边界和转咨询条件。
4. 已售用户的承诺不能单方面缩减，应给过渡方案。

### 路由

模块 04 → 模块 15；涉及既有承诺时增加合同与消费者权益审查。

## 测试三｜有大量客资但成交低

### 用户输入

“每月有三百多条线索，成交很少，是不是应该做高价课？”

### 错误输出

按流量规模直接设计高价产品阶梯。

### 正确输出

1. 先区分线索来源、任务、付款者和产品适配。
2. 判断问题在产品承诺、价格、销售跟进还是履约证据。
3. 模块 04只处理产品适配与验证。
4. 销售过程转模块 13，用户研究转模块 05。

### 路由

模块 04 → 模块 05／13。

## 内部测试结论

- 三类入口可以区分。
- 不会用同一张产品画布强行覆盖所有阶段。
- 输入不足会降级为假设与采集动作。
- 对高风险、既有承诺和合规问题能够停止。
