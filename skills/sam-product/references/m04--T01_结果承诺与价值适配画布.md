# 结果承诺与价值适配画布

## 使用目的

把“我想卖什么”改成用户任务、结果承诺、交付机制与证据相互对应的产品定义。

## 第一步｜只选一个场景

```text
谁：
发生了什么触发事件：
当前要完成什么任务：
截止或失败代价：
当前替代方案：
谁付款／谁使用／谁验收：
```

## 第二步｜拆三类进展

| 维度 | 用户希望发生什么变化 |
|---|---|
| 功能 | 完成什么任务 |
| 情绪 | 减少什么不确定与焦虑 |
| 社会 | 希望被谁怎样看待或取得什么身份结果 |

三者都可以记录，但产品不能用情绪承诺替代功能交付。

## 第三步｜写有限承诺

```text
本产品帮助谁：
在什么场景：
从什么状态：
到什么可检查状态：
通过什么机制：
需要用户完成什么：
不承诺什么：
```

## 第四步｜做一一对应

| 用户关键任务／阻力 | 交付物 | 生效机制 | 检查信号 |
|---|---|---|---|
|  |  |  |  |

没有对应关系的交付物移出主产品。

重要任务没有交付机制，说明产品缺口仍在。

## 第五步｜证据检查

- 用户任务证据。
- 能力与案例证据。
- 交付过程证据。
- 结果证据。
- 失败和边界证据。

## 标准输出

1. 场景化用户定义。
2. 一句话有限承诺。
3. 结果层级。
4. 交付与用户责任。
5. 不包含事项。
6. 当前最危险假设。

## 停止条件

- 同时服务多个冲突场景。
- 结果主要不受产品控制。
- 用户任务只有主观想象。
- 产品涉及资质、安全或法律问题但未核查。
