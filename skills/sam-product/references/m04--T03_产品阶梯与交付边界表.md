# 产品阶梯与交付边界表

## 第一步｜先画任务链

不要先写免费、低价、高价。

先写用户连续面对的不同任务。

```text
任务 1：
完成信号：
任务 2：
完成信号：
任务 3：
完成信号：
```

## 第二步｜每个产品单独填写

| 项目 | 内容 |
|---|---|
| 产品名称 |  |
| 目标任务 |  |
| 进入条件 |  |
| 结果承诺 |  |
| 交付机制 |  |
| 用户责任 |  |
| 包含 |  |
| 不包含 |  |
| 反馈与回复规则 |  |
| 容量 |  |
| 退出条件 |  |

## 第三步｜标关系

- 前置。
- 替代。
- 升级。
- 并行。
- 退出。

每条升级必须写出现实任务变化，不得只写“购买意愿更强”。

## 第四步｜重叠与断层审计

### 重叠

- 两个产品承诺相同结果。
- 同一服务被重复收费。
- 价格变化但交付机制不变。

### 断层

- 内容引来需求但没有产品。
- 产品成交后没有使用路径。
- 知识库问题无法转入咨询或课程。
- 高价服务依赖前置能力但未筛选。

## 第五步｜社群特别规则

必须写：

- 答疑时间和频次。
- 是否看稿、是否批改。
- 单个用户上限。
- 隐私与广告规则。
- 什么问题转付费服务。

## 标准输出

- 任务链与产品图。
- 每个产品边界。
- 五类关系。
- 三个最大重叠或断层。
- 下一项产品修改。
