# 来源登记与原创性边界

## 一、当前真源

本 Skill 的运行真源是《叁木完整原子库 V2.0｜Skill-ready 成熟候选版》。

当前快照：

- 17 个自媒体与自然流短视频模块。
- 203 张方法原子卡。
- 68 份工具合同。
- 17 个案例与反例入口。
- 79 张来源证据卡。
- 全库 540 个文件，内部链接缺失数为 0。

来源版本写入 `state_delta.versions.atom_library`。

Skill 不在运行时依赖桌面原子库路径。

必要规则已经转成自身的 references，确保交付给其他用户后仍能独立运行。

## 二、叁木主干

以下内容决定诊断顺序和最后裁决：

1. 先判断为什么要经营媒体端口，再决定做多大范围。
2. 从真实任务、个人积累和公共证明出发，不从虚构人设出发。
3. 区分市场成立、个人能进入、产品可交易和交付可兑现。
4. 把用户放进处境、任务、替代、风险和决策链中理解。
5. 定位约束市场、用户、问题、角色、结果、产品与内容。
6. 内容从对标研究、选题、包装、脚本进入传播和关系结果。
7. 流量、关系、交易与交付分别成立，不能互相替代。
8. AI 只放大已经明确的任务、规则和材料，不替主体作市场、承诺与责任决定。
9. 每轮只修最近一个可干预断点，把结果写回状态和数字资产。

本 Skill 对这些内容的运行化结果：

- S0—S6 项目阶段。
- 17 模块必要链，而不是 17 项固定问卷。
- F/O/I/H/D/U 证据账本。
- 已形成／有信号／未验证三层能力描述。
- 一个主问题、一个替代解释和一个区分实验。
- 保留、修改、暂不处理。
- 七天证据动作、三十天验证和下一 Skill 交接。

## 三、外部理论的角色

外部理论不提供现成答案，只补五种东西：

- 判断尺：说明什么条件成立、什么条件不成立。
- 因果解释：解释变量之间为什么可能有关。
- 反例：提醒某条规则何时会失效。
- 取证方法：说明需要观察什么行为和数据。
- 风险边界：限制过度承诺、错误归因与盲目放大。

核心来源族及其进入位置：

| 来源族 | 被吸收的判断 | 进入模块 |
|---|---|---|
| 市场营销、需求与定位 | 需求行为、替代、顾客价值、竞争坐标、外部心智 | 02、04、05、06 |
| 商业模式与单位经济 | 价值、渠道、关系、成本、收入与交付相互约束 | 04、15、16 |
| 社会学与社会心理学 | 身份、承认、资本、信号、弱关系、呈现与群体认同 | 01、03、05、06、12 |
| 传播学与广告学 | 媒介、框架、注意力、说服、扩散、相关性与测试 | 07、09、10、11、12 |
| 决策心理与行为科学 | 风险、损失、承诺、认知失调、实施意图与自我效能 | 05、11、15、17 |
| 学习、案例与实验方法 | 经验归因、机制迁移、基线、反例和前向验证 | 03、08、14、17 |
| 平台官方资料 | 数据字段、推荐说明、治理边界与规则时效 | 07、13、14 |
| 叁木项目证据 | 自然流、矩阵生产、实体承接、AI 内容协作与团队交接 | 全链裁决与案例边界 |

详细来源、证据等级、核验状态与失效日期，以原子库 `03_证据层` 和来源地图为准。

最终诊断默认不堆作者名字。

用户询问依据时，必须区分：原作者结论、后续研究或官方资料、叁木改写规则、当前项目事实。

## 四、外部同类工具的使用边界

外部同类工具只用于研发期检查产品颗粒度和交互完整度：

- 是否有独立入口。
- 是否先说明交付。
- 是否分轮追问。
- 是否有输入、判断、输出和结束条件。
- 是否能保存状态并路由下一任务。
- 是否让用户得到清晰结论与可执行方案。

不把它们作为运行时依赖。

不复制独有名称、用户分层、标志句式、案例归属和原有判断顺序。

## 五、外部规则进入本 Skill 的门槛

一条规则必须同时满足：

1. 解决 17 模块中一个明确问题。
2. 不与叁木的完整结果链冲突。
3. 有适用对象、关键变量、最低通过条件和失败信号。
4. 有证据入口、反例和边界。
5. 能改变本轮判断或行动，而不只是提供漂亮解释。
6. 去掉作者名字后仍然可以独立运行。
7. 不把历史平台经验冒充当前规则。

不满足时，只能作为候选假设或案例，不进入裁决主干。

## 六、明确拒绝的吸收方式

- 把一本书的目录改成 Samskill 流程。
- 把多个框架并排列成理论清单。
- 只替换词语，却保留对标 Skill 的表达和用户分层。
- 用宏观趋势替代真实用户行为。
- 用外部案例冒充叁木自有结果。
- 把蒸馏 Skill 的扩写当成原作者原话。
- 因为来源权威，就跳过当前项目事实。

## 七、当前验证状态

本版本可以作为首轮公开测试版，不宣称已经跨用户稳定复现。

发布前必须完成静态校验、入口测试、典型场景试跑和权限检查。

后续版本升级需要新增：

- 真实新用户的低信息问诊记录。
- 不同项目角色的理解与执行反馈。
- 七天动作完成后的前向结果。
- 下一 Skill 接收状态后的串联验证。

没有前向结果时，只能说“规则与交互成熟候选”，不能说“市场验证完成”。
