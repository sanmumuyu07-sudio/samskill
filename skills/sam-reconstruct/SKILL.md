# 叁木｜参考内容改写与重构

## 交付目标

先判断用户要的是保留原稿内容和逻辑的参考型改写，还是借参考稿建立新问题的独立原创重构。

参考型改写要让用户看到原稿保留了什么、哪些材料已经适配，并得到一份可以继续修改或发布的稿件。独立原创重构则要让用户知道原内容为什么成立、当前项目新增了什么，以及新命题和论证是否成立。

## 必读资料

启动后依次完整读取：

1. `references/sanmu-intake-and-delivery-contract.md`。
2. `references/reference-adaptation-contract.md`。

任务判定为独立原创重构时，再继续读取：

3. `references/original-reconstruction-contract.md`。
4. `references/content-framework-selector.md`。
5. `references/content-form-selector.md`。
6. `references/sanmu-writing-standard-v2-runtime.md`。

独立原创重构需要案例时读取 `references/content-framework-case-index.md`；需要追溯对标方法和理论边界时读取 `references/source-map.md`；准备交付时读取 `references/output-contract.md`。参考型改写的分析、成稿与交付均以 `reference-adaptation-contract.md` 为准。

第一次使用、用户问“要提供什么”或材料不足时，完整读取 `assets/input-card.md`。最终用户版交付完整读取 `assets/output-template.md`，按当前任务模式只填写对应分支。

不要把内部原子编号和版权判断过程写进面向客户的正式文案，但必须保留来源、引用和授权提醒。

## 第零步｜边界

允许研究公共事实、通用结构、内容任务和成立机制。自有或已获授权的材料，可以按授权范围高保真处理。

对公开第三方材料不执行：逐句同义替换、仅调换段落来规避重合、保留标志性比喻与独创命名、模仿特定作者声音、规避检测、隐藏来源或处理无权使用的私密材料。自有或已获授权材料可以在授权范围内做句子级修订和高保真编辑。

遇到上述请求时，拒绝该动作，但继续提供摘要、评论、机制拆解、引用式回应或从新问题开始的原创方案。

本 Skill 不提供法律意见，也不保证绝对不存在版权风险。

## 第一步｜先判改写模式

按顺序读取本轮对话、用户指定参考材料、当前项目资料、作者风格卡、产品状态和有效上游交接。不得重复索取已有内容。根据 `reference-adaptation-contract.md` 判定 `faithful_adaptation` 或 `independent_reconstruction`。

判定为 `faithful_adaptation` 后，直接执行参考型改写合同并在该合同内完成交付，跳过本文后续的第二至第八步和“按深度交付”。不强制建立新命题、独立贡献、多候选框架和新方法论。判定为 `independent_reconstruction` 后，继续执行后续原创重构流程。

独立原创重构再自动选择用户端交付深度：快速判断、共创成稿或研究审计。用户未指定时不先弹出模式菜单；具体规则以重构合同为准。

信息不足时，先说明最终会交付什么，最多问两个能改变结果的问题：

1. 参考材料的来源、权限和预期用途是什么？这次准备影响谁的什么理解或行动？
2. 当前项目能提供哪些独立经历、用户语言、数据、案例或产品判断？作者以什么位置讲，哪些事实与表达不能改变？

参考正文无法访问时，索取正文、转录或可分析片段，不假装已经读取。

## 第二步｜建立参考指纹和材料分层

拆出：目标用户、处境、问题、主张、证据、案例、概念、结构顺序、情绪路径、标题、开头、结尾、行动入口和高识别度表达。

逐项标记：

- 可复用公共材料。
- 需要标注来源。
- 只可研究机制。
- 不可用或需要授权。
- 权利或事实未知。

没有完成这一步，不进入写稿。

上游对标交接已经包含同一版本的参考指纹、成立机制、条件差与权利边界时，验证后直接继承，不重复展示完整拆解。

## 第三步｜提取机制，不复制表面

用“条件—动作—中间反应—结果—替代解释”说明原内容为何可能成立。

然后填写差异矩阵：目标用户、现实处境、核心问题、主张、证据、案例、推理结构、作者角色、行动和产品连接。

如果新方案只改变词语、顺序、行业名或案例名，判定不通过。

## 第四步｜通过方向成立门

在正式大纲前检查：

1. 内容对象及其现实情境。
2. 作者位置与进入权。
3. 可使用的真实独立材料。
4. 内容去向：要改变的理解或行动；确有商业任务时再写产品承接。

已有状态可以确认的直接继承。存在会改变主张、案例或行动的歧义时，先给推荐方案，再最多问两个问题。

不把每条内容都强制连接产品。

## 第五步｜建立当前项目的独立贡献

先不看原文措辞，独立完成：

1. 任务句。
2. 唯一核心主张。
3. 根据、推理连接、成立限定和最强异议。
4. 作者自己的材料及其可支持与不可支持项。
5. 新内容对公共讨论增加了什么。

证据不足时，降低结论、补研究或交付选题与补证单，不生成伪原创完整稿。

## 第六步｜选择框架与形式

根据内容任务、用户状态、材料、作者进入权、赛道、商业距离、载体和风险生成二到三个候选框架。

每个候选说明适配、材料缺口、风险和验证信号；推荐一个主框架，说明为什么本次不选第二名。

再选择内容形式。框架与形式不得混为一谈。

## 第七步｜先交付大纲，再按大纲门成稿

先交付大纲与段落任务。

共创成稿模式中，用户认可大纲后再完成全文；用户要求修改时先改大纲。用户明确要求直接写且方向门已经成立，可以同轮交付大纲和全文。方向仍有实质歧义时，不生成伪确定全文。

完成标题、封面文字、开头、正文、案例、异议、行动与收束。

遵守叁木写作标准，但作者不是叁木时，以用户自己的风格卡为准；没有风格卡时使用中性清楚表达，不伪造口吻。

需要引用时明确标注。不得用“有人说”“据说”隐藏可识别来源。

## 第八步｜十维原创审计

对照命题、顺序、证据、案例、概念、比喻、标题、开头、结尾和语言。

结论只能是：通过、限制通过、不通过。

不通过时指出返工层级；不通过的文本不得进入发布审计。

## 按深度交付

所有模式先交付一句话结论、原内容成立机制、当前项目需要保留与改变、方向门状态、下一步和简版风险。

快速判断默认控制在一屏左右，不展开差异矩阵和内部审计过程。

共创成稿增加框架取舍、新选题、大纲，并按大纲门状态决定是否交付完整新稿。

研究审计增加来源分层、完整差异矩阵、框架选择、完整新稿、十维审计明细和引用授权待办。

先给用户能直接理解的判断，再给内部检查表。不得只交一份“改写后文案”。

## 路由与交接

- 只需对标研究，不需要新稿：转 `sam-benchmark`。
- 缺事实、用户语言或案例：转 `sam-research`。
- 新选题尚未成立：转 `sam-topic`。
- 新稿已经独立成立但需优化：转 `sam-edit`。
- 准备发布：转 `sam-audit`。

每次只进入一个当前必要入口。

## 状态与权限

两种任务分开保存状态：

- `faithful_adaptation`：保存 `output_depth`、`source_status`、`source_map`、`rights_classification`、`preserve`、`adapt`、`rebuild`、`opening_action`、`persona_materials`、`author_confirmations`、`user_feedback`、`remaining_actions`、`intake` 和 `handoff`。
- `independent_reconstruction`：保存 `output_depth`、`output_depth_source`、`source_status`、`source_fingerprint`、`rights_classification`、`upstream_research_reused`、`mechanism_hypothesis`、`direction_gate`、`independent_contribution`、`difference_matrix`、`framework_selection`、`form_selection`、`new_topic`、`new_argument`、`outline`、`outline_gate`、`draft_version`、`overlap_audit`、`originality_gate`、`remaining_actions`、`intake` 和 `handoff`。

未经明确授权只输出预览，不写入项目、不发布、不联系原作者或客户、不覆盖真源。

## 三通质检

- **判断通**：`faithful_adaptation` 检查来源的问题、判断、重点、段落任务和推进顺序是否仍在，以及有没有不必要的原创化；`independent_reconstruction` 检查新主张能否回到当前项目事实、来源独立性是否成立。
- **用户通**：用户先看到能不能用、为什么和下一步，不先看到复杂版权术语。
- **行动通**：补证、引用、授权、返工与发布门都能检查和停止。

任一通失败，先返工再交付。
