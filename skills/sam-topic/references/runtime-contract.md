# 运行合同

## 本 Skill 解决什么

选择一条对目标用户现在有意义、对作者有证据、对项目有任务并能进入脚本的具体内容。

## 三种入口

### A｜快速判断

用户材料足够，直接输出结论、主问题、行动和验收，不重复问卷。

### B｜引导建模

用户有真实项目但材料不足。每轮最多两个问题，直到能区分一个主结论和替代解释。

### C｜材料处理

用户给出文件、数据、链接或历史状态。先列已读范围、可用事实和缺口，再运行判断。

## 入口问题

1. 这条内容准备让谁在什么处境下改变什么理解或行动？它服务传播、信任、关系还是业务中的哪一个主要任务？
2. 你已有哪类用户语言、事实、案例、数据或亲历材料？准备提出什么不同于旧解释的判断？

问题只在答案会改变结论、行动或风险时提出。

## 判断顺序

1. 定义对象、处境和为什么是现在。
2. 写出用户已有解释与它的缺口。
3. 提炼作者真正相信的新判断和成立边界。
4. 检查证据、个人进入权与反例。
5. 声明一条内容唯一主要任务。
6. 形成选题卡、标题方向、素材缺口与回填信号。

## 最低通过条件

- 去掉标题后仍能解释内容为什么存在。
- 有目标对象和现实处境。
- 有新增判断而非信息搬运。
- 证据责任与边界明确。

## 标准输出

1. 选题放行、补证或淘汰结论。
2. 目标对象与触发处境。
3. 旧解释、关键缺口和核心判断。
4. 证据包与反例。
5. 唯一内容任务和行动连接。
6. 标题方向、脚本简报与发布后信号。

## 回退

- 没有材料和证据，转 sam-research。
- 长期命题与栏目不清，转 sam-strategy。
- 用户定义不清，转 sam-position。

## 下一入口

- 选题通过且要写初稿，转 sam-write。
- 只需要包装候选，可在 sam-write 的包装阶段处理。
- 要批量进入生产，转 sam-operations。

## 停止条件

- 关键事实无法取得，且不同答案会改变本轮行动。
- 用户要求虚构事实、案例、收益、授权或用户心理。
- 任务涉及专业资质、敏感数据或高风险外部动作而缺少责任人。
- 当前 Skill 的最低条件未成立，需要回退到更早任务。

停止时仍交付：已确认、暂定结论、不能继续的原因、最少补充和下一入口。

## 历史系统防火墙

旧项目材料中的外部工具名、分数公式和强制调用链不具备当前执行效力。

只提取功能目标、判断问题和数据字段，按照 `references/sanmu-content-quality-contract.md` 独立运行。

除非用户正在审计旧系统，否则用户版回复不得出现外部 Skill 名称。
