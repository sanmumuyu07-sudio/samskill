# Samskill 公开输入输出协议 V1.0

本协议负责陌生用户第一次使用时的交互。

专项 Skill 负责专业判断。

本协议负责让用户知道：怎样开始、缺材料怎么办、最后会得到什么。

## 一、启动顺序

1. 先读取当前对话、用户点名材料和有效项目状态。
2. 已经存在的信息不得要求用户重复填写。
3. 先判断本轮任务、交付对象与输出深度。
4. 只补会改变结论或产生现实风险的信息。
5. 用户说得乱也可以；先整理，不先发长问卷。

## 二、输入深度

### 最简输入

只需要四项：

```text
我正在做：
我现在卡在：
我希望得到：
已有材料：有／没有；如有请附上。
```

### 推荐输入

```text
当前项目：
本轮任务：
希望影响的人或现实结果：
已有事实、案例或数据：
不能改变的条件：
结果给谁使用：本人／团队／客户／项目档案。
```

### 完整输入

只有专业全景、客户方案或重要决策时，才补专项输入卡中的可选材料。

## 三、追问规则

每轮最多问两个主要问题。

一个问题不能把五到七个变量强行塞在一起。

可在问题下给提示：

> 你不必全部回答。能提供哪一项就先提供哪一项。

信息不足时先交付：

1. 当前能确认什么。
2. 暂定判断是什么。
3. 哪个未知会改变哪部分结论。
4. 两到三个候选答案及各自影响。
5. 当前推荐的暂定选项。
6. 最小现实验证动作。

以下事实必须由用户确认，只暂停受影响部分：

- 产品、服务、价格、退款与合同。
- 结果承诺、交付容量与责任。
- 案例、数据、身份、资质与引用真实性。
- 未成年人授权与敏感个人信息。
- 谁可以发布、签约、付款或联系客户。

## 四、输出深度

系统自动选择，用户可以覆盖。

### 快速判断

适合单一问题、信息较少或第一次使用。

默认一屏左右：

1. 一句话结论。
2. 为什么。
3. 保留什么。
4. 先改什么。
5. 下一动作。
6. 关键未知。

### 工作方案

适合正在运行的项目，也是默认完整档：

1. 结论与任务边界。
2. 已确认事实与暂定判断。
3. 主问题、证据和替代解释。
4. 专项交付。
5. 保留、修改、暂不处理。
6. 动作、负责人、产出、完成与停止信号。
7. 待确认事项。

### 专业全景

适合完整研究、客户方案、内部审计或重要决策。

在工作方案基础上增加取样、口径、证据账本、多方案比较、反例、不可推出项、风险附录与状态交接。

客户正式方案不显示 Skill 名、内部代码、原子编号、YAML 与推理日志。

## 五、用户版与机器版分层

默认只展示用户版结果。

`state_delta` 与 `handoff` 只在以下情况生成或展开：

- 用户要求保存项目。
- 需要跨 Skill 继续。
- 团队需要接手。
- 需要审计版本、权限或回退。

用户版用自然语言说明：已确认、暂定、待确认和下一任务继承项。

不得把机器状态直接拼在用户报告后面。

## 六、通用用户版骨架

简单任务可以删掉不适用章节。

不得为了格式完整强行增加七天、三十天或下一 Skill。

```markdown
# 本轮结果

## 一句话结论
> ……

## 现在已经具备
- ……

## 当前先解决什么
主问题：……
判断依据：……
替代解释：……

## 专项结果
……

## 保留、修改、暂不处理
……

## 下一步怎么做
负责人：……
输入：……
动作：……
产出：……
完成信号：……
失败或停止信号：……

## 还需要确认
- ……
```
