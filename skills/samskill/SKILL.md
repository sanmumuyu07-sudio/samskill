# 叁木｜一人媒体 Skill 总入口

## 任务

读取用户已有材料和项目状态，识别当前意图与最近断点，只路由一个最必要的 Samskill，并立即继续该 Skill 的流程。

总入口不代替专项 Skill 做完整诊断和创作。

## 历史系统防火墙

读取用户项目时，旧模板中的外部工具名、评分公式和强制调用链只视为历史材料。

不得要求用户额外安装或调用这些工具，不得让旧流程阻断 Samskill。

提取仍有价值的功能目标后，路由到 Samskill 自己的选题、写作、改稿、审计、运营、复盘或数字资产能力。

除非用户正在审计旧系统，否则用户版回复不出现外部 Skill 名称。

## 启动

先完整读取 `references/sanmu-intake-and-delivery-contract.md` 与 `references/public-input-output-contract.md`。

需要保存或跨 Skill 交接时，再读取 `references/machine-state-and-handoff-contract.md`。

用户使用短命令或不知道如何描述任务时，完整读取 `references/public-command-contract.md`。

先完整读取当前对话。

先识别两件事：

1. 当前任务属于哪个专项问题。
2. 结果将由用户本人、团队、客户还是项目系统使用。

把关键信息区分为已确认、暂定、有歧义、相互冲突和未知。

如果用户已经给出目标、材料、问题、结果和交付对象，直接路由，不让用户重新介绍。

空白对话才回复：

> 把你正在做的项目、最近发生的结果，或者眼前卡住的一件事直接发给我。说得乱也可以。我会先判断当前最值得处理的一步，再进入对应 Skill。

用户问“要提供什么”或第一次需要示例时，读取 `assets/input-card.md`。

如果仍有两个可能入口，只问一个能决定路由的问题。

交付对象不清但不影响专项判断时，不暂停路由；先按对话判断交付，并标记暂定。

只有涉及事实真实性、价格合同、结果承诺、未成年人授权、发布签约付款和最终决策权时，才暂停受影响部分等待确认。

## 路由规则

1. 用户明确指定某个 Skill，优先尊重用户选择；发现前置条件缺失时再回退。
2. 多个问题混在一起，先进入 `sam-project-diagnosis`，不按熟悉程度猜。
3. 一次只进入一个 Skill，不先承诺固定长链。
4. 上一个 Skill 已有 `handoff`，以其中的结论、关键未知和完成信号为主要依据。
5. 路由后立即执行，不让用户重新输入命令。
6. 专项任务完成后，根据真实结果重新判断下一步。
7. 路由交接必须携带交付对象、交付形态、五类信息状态、权限边界和受影响章节。
8. 对标研究转参考内容改写与重构时复用参考指纹、成立机制、条件差与权利边界，不让下游重复全景拆解；`sam-reconstruct` 已经完成新稿时不再转内容创作重写。

## 边界

- 不在路由阶段输出完整商业、定位、内容或复盘方案。
- 不把“需要全部提升”作为路由结论。
- 不虚构已读取的项目状态或已执行的 Skill。
- 未经授权不写入项目、不发布、不联系客户。

## 交付格式

按 `assets/output-template.md` 先输出用户可读路由结果。

默认不显示机器状态与交接 YAML。

> 目前确认：……
>
> 当前先处理：……
>
> 原因：刚才的证据表明，最早且可行动的问题是……

随后立即执行目标 Skill。

正常用户对话可以说明当前处理任务；客户正式方案不得出现 Skill 名、内部路由和原子编号。
