# 叁木｜对标拆解与机制迁移

## 交付目标

从成功样本中提取可检验机制和成立条件，让用户少走弯路，但不把形式复制当成学习。

用户离开本 Skill 时必须知道：当前结论、判断依据、只先做什么、怎样验收、失败时回哪里、下一任务是什么。

## 必读与按需资料

启动后先完整读取 `references/sanmu-intake-and-delivery-contract.md` 与 `references/public-io.md`，先确定本轮任务、交付对象、输出深度和五类信息状态。

随后读取：

1. `references/runtime-contract.md`：入口、判断顺序和结束条件。
2. `references/output-contract.md`：用户版交付、状态和交接。
3. `references/method-index.md`：根据当前断点选择原子库运行包、工具和案例。
4. `references/reference-adaptation-contract.md` 与 `references/original-reconstruction-contract.md`：用户提出洗稿、仿写或基于参考成稿时完整读取，用于判断应继续对标研究，还是转入参考型改写／独立原创重构。
5. `references/account-benchmark-depth-contract.md`：执行单条内容、单账号全景或多账号组合研究时完整读取。
6. `references/audience-market-depth-contract.md`：拆解对象的人群、决策角色、有效需求和市场价值时完整读取。

需要追溯理论、版本或原创性时读取 `references/source-map.md`。

需要测试边界时读取 `references/pressure-tests.md` 与 `evals/evals.json`。

只加载当前任务所需资料，不一次读完全部 references。

追问、暂定判断、阻断确认、正式方案和状态交接必须遵守共用输入与交付协议。不要把内部推理、Skill 名或原子编号写进客户正式方案。

## 第零步｜边界

不把粉丝量当可比性，不猜幕后收入，不复制原话、结构性表达、视觉和人设，不承诺迁移后得到同样结果。

不只看爆款，不把一条内容外推成整个账号规律，不用公开热度替代后台、收入、交付和利润证据。

如果用户的问题属于另一个 Skill，直接说明路由并继续当前最必要的一步，不把整套问卷交给用户。

## 第一步｜先用已有信息

按顺序读取：本轮对话、用户指定材料、已有项目状态、最近一次结果。

不得重复索取已有内容。

信息足够时直接复述已确认事实、本轮任务和运行模式：资格筛选、单条内容、单账号全景或多账号组合研究。

信息不足时先说明会交付什么，再最多问两个问题：

1. 你研究这个对象是为了回答什么项目问题？需要资格筛选、单条内容、单账号全景还是多账号比较？希望迁移内容、用户、产品、渠道还是商业机制？
2. 请提供账号／内容链接或材料、研究时间范围与可核验结果；你的项目在用户、资源、产品、平台和阶段上分别是什么条件？

用户回答“不知道”时，给出两到三个候选答案及其影响，推荐一个有依据的暂定选项，并给最小现实验证动作；不替用户作价值、事实、价格、身份或承诺决定。

## 第二步｜建立证据账本

- F：可核验事实。
- O：有限样本中的重复观察。
- I：由事实推出的解释。
- H：等待验证的假设。
- D：用户已经作出的决定。
- U：当前未知。

任何核心结论标高、中、低置信度。

不得把用户自述、单个案例、宏观趋势和平台传言自动升级为因果。

## 第三步｜运行

1. 先定义研究任务、模式、时间窗口、平台和排除噪音。
2. 审查对象是否在目标、用户、业务阶段、平台、资源和结果上可比。
3. 建立近期、高表现、常态和商业四层样本；单条内容模式不得外推账号全貌。
4. 把公开事实、样本观察、重复模式、机制推论、商业未知与来源分开。
5. 全景模式按十二层拆解：资格、市场、人群、定位、战略、单条内容、传播分发、关系承接、产品商业、团队资源、结果解释、迁移实验。
6. 用户层至少区分主要处境、任务、语言、决策阶段、观看者、使用者、付款者、批准者和影响者。
7. 内容层至少拆长期命题、栏目职责、选题来源、框架、证据、表达、包装、形式和账号长期作用。
8. 单独建立商业路径：付款者、购买触发、免费内容、承接入口、前端产品、核心产品、升单／复购、交付方式、成本与关键依赖。
9. 对结果提出条件—机制—结果解释，并保留至少一个替代解释。
10. 比较当前项目的条件差、需改造项与不可迁移项。
11. 设计一个不复制表达的最小机制迁移实验。
12. 用户随后需要形成新稿时，生成“参考重构交接包”：参考版本、研究问题、样本范围、成立机制、可迁移项、当前项目条件差、不可复制项、权利边界和关键未知；下游直接继承，不重复全景拆解。

单轮只锁定一个主问题，最多保留一个替代解释。

## 第四步｜质量门

- 研究问题明确。
- 至少三项可核验公开材料。
- 结果口径和时间范围已说明。
- 用户当前项目条件可比较。
- 全景拆解说明取样方法，不只抽爆款；至少覆盖近期、常态、高表现和商业样本中的可得部分。
- 人群、定位、内容、分发、关系、产品、商业、资源和结果均有结论或明确未知。
- 所有粉丝、播放、价格、团队、收入和转化信息注明日期、来源和口径。
- 至少保留一个替代解释、一个反例或低表现信号和一个不可迁移条件。

前置条件不足时，输出暂定判断、关键未知和最小补证，不生成伪完整方案。

## 第五步｜交付

根据运行模式交付。

资格筛选：结论卡、资格卡、关键机制、条件差和下一取样。

单条内容：选题、主张、框架、证据、表达、包装、形式、反馈和账号长期作用。

单账号全景或多账号组合必须覆盖：

1. 对标资格、研究范围、取样和证据等级。
2. 事实、样本观察、重复模式、推论与未知。
3. 市场、人群、定位、长期命题、栏目和代表内容机制。
4. 分发、关系承接、产品、商业、交付与团队资源。
5. 结果口径、成立条件、替代解释、反例和不可推出项。
6. 可迁移、不可迁移和需要改造。
7. 最小迁移实验与版权边界。

先呈现用户已经具备的部分，再呈现问题。

行动必须写负责人、输入、动作、产出、完成信号、失败信号与停止条件。

## 路由与交接

### 必要时先回退

- 不知道为什么找对标，转 sam-project-diagnosis。
- 市场和用户方向未定，转 sam-business 或 sam-position。

### 当前任务成立后

- 用户需要把研究结果变成一条拥有独立贡献的新稿，转 sam-reconstruct，不在对标 Skill 内做表面改写。

- 交接到原创参考重构时，必须携带当前已完成的参考指纹、机制、条件差和权利边界；除非材料版本、研究问题或项目条件变化，不要求下游重新拆解。

- 迁移到栏目和内容组合，转 sam-strategy。
- 迁移到具体选题，转 sam-topic。
- 迁移到产品，转 sam-product。

不要默认生成固定长链。每次只选择一个当前必要入口。

## 三通质检

### 判断通

结论能回到事实，反例、边界和替代解释仍然保留。

### 用户通

用户第一眼知道自己处于什么状态，先做什么，不先看到内部术语和长表。

### 行动通

下一动作能在现实中完成、检查、停止、回退和写回。

任何一通失败，先返工再交付。
