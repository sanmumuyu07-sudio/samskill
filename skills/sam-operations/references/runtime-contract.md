# 运行合同

## 本 Skill 解决什么

在不牺牲事实、内容质量和后端承接的前提下，让内容从材料连续走到发布、互动与复盘。

## 三种入口

### A｜快速判断

用户材料足够，直接输出结论、主问题、行动和验收，不重复问卷。

### B｜引导建模

用户有真实项目但材料不足。每轮最多两个问题，直到能区分一个主结论和替代解释。

### C｜材料处理

用户给出文件、数据、链接或历史状态。先列已读范围、可用事实和缺口，再运行判断。

## 入口问题

1. 当前内容处于选题、脚本、待拍、待剪还是待发布？目标平台、频率和定义完成是什么？
2. 由谁决定、执行和审批？单条中位工时、返工率、库存、设备、预算和后端承接能力分别是多少？

问题只在答案会改变结论、行动或风险时提出。

## 判断顺序

1. 检查选题、脚本和发布审计是否通过。
2. 建立唯一内容ID与O0—O7状态。
3. 明确决定人、执行人、审批人、产物和质量门。
4. 按产能、库存、返工和后端容量确定频率。
5. 完成平台包装、发布假设、互动与关系入口。
6. 异常按最后通过状态回退，并写入复盘。

## 最低通过条件

- 选题、脚本与包装通过。
- 角色权限和定义完成明确。
- 平台规则来源和核验日期可追溯。
- 发布、隐私和客户材料有授权。

## 标准输出

1. 当前生产状态和阻塞。
2. 内容ID、负责人和截止。
3. 拍摄剪辑包装任务单。
4. 三道质量门与返工责任。
5. 平台发布、互动和关系入口。
6. 产能库存看板、异常回退和复盘字段。

## 回退

- 内容尚未写完，转 sam-write 或 sam-edit。
- 发布审计未通过，转 sam-audit。
- 定位与平台严重冲突，转 sam-position。

## 下一入口

- 发布后进入 sam-retro。
- 互动与线索需要分流，转 sam-relationship。
- 生产依赖核心操盘手，转 sam-assets 建AI和团队交接。

## 停止条件

- 关键事实无法取得，且不同答案会改变本轮行动。
- 用户要求虚构事实、案例、收益、授权或用户心理。
- 任务涉及专业资质、敏感数据或高风险外部动作而缺少责任人。
- 当前 Skill 的最低条件未成立，需要回退到更早任务。

停止时仍交付：已确认、暂定结论、不能继续的原因、最少补充和下一入口。

## 历史系统防火墙

旧项目材料中的外部工具名、分数公式和强制调用链不具备当前执行效力。

只提取功能目标、判断问题和数据字段，按照 `references/sanmu-content-quality-contract.md` 独立运行。

除非用户正在审计旧系统，否则用户版回复不得出现外部 Skill 名称。
