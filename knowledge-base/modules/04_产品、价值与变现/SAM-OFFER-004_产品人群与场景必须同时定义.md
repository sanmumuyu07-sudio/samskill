# 产品、人群与场景必须同时定义

## 叁木判断

> 人群回答“谁”，场景回答“什么时候、为什么现在、受什么限制”。只有二者同时存在，产品才能被正确选择和使用。

“创业者”“宝妈”“实体老板”“想做 IP 的人”都太宽。

同一个人处在不同场景，会选择完全不同的产品。

## 一、场景至少包含六项

1. 触发事件。
2. 当前任务。
3. 已经尝试的方案。
4. 截止时间。
5. 可调用资源。
6. 失败代价。

例如“有实体生意的老板”不是场景。

“三个月后准备开第二家店，现有获客依赖团购，想测试老板 IP 是否能稳定带来咨询”才开始形成产品场景。

## 二、阶段比宽泛身份更能决定交付

同样是想做个人 IP：

- 没发过内容，需要最小启动。
- 已有内容无反馈，需要断点诊断。
- 有流量无成交，需要产品和承接。
- 有团队无迭代，需要判断标准与协作系统。

这四类人不能进入同一份固定作业。

## 三、一个产品不要混多个冲突人群

零基础用户需要解释、示例和低风险动作。

成熟团队需要数据、权限、责任和跨角色协同。

如果同一产品同时服务二者，常见结果是：新人听不懂，成熟用户觉得浅。

## 四、决策角色

至少区分：

- 提出需求的人。
- 付款的人。
- 使用的人。
- 配合执行的人。
- 验收结果的人。

B2B 与团队型项目尤其不能把这些角色压成“用户”。

## 五、行动步骤

1. 用一次真实触发事件开头。
2. 写用户当前阶段和已有动作。
3. 记录替代方案与限制。
4. 标出付款、使用和验收角色。
5. 写产品适合与不适合的人。
6. 分场景测试同一句承诺是否仍然成立。

## 六、案例

“知识库+社群”如果面向所有想做自媒体的人，产品边界会迅速失控。

更可检验的定义是：已经有一项现实业务或专业任务，愿意自己执行，希望按全流程地图判断断点并获得集中答疑的人。

没有现实任务、只想寻找身份感的人，不应被承诺通过阅读获得结果。

## 七、反例

用“女性成长”把求职、婚姻、创业、育儿和情绪疗愈放进同一产品，只因为这些人都可能是女性。

这是人口标签，不是产品场景。

## 八、输出标准

- 场景化人群句。
- 当前阶段与触发事件。
- 任务、约束和替代方案。
- 五类决策角色。
- 适合、不适合与需转路由人群。

## 九、来源与冲突处理

- 价值主张画布要求一个客户画像对应具体任务、痛点和收益。
- JTBD 强调进展发生在具体处境中。
- 本原子不否定人口特征，但拒绝用人口特征代替购买和使用场景。
