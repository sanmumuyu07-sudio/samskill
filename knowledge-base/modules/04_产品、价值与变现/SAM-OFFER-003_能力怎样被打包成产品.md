# 能力怎样被打包成产品

## 叁木判断

> 能力只有被限定为可解决的任务，并被转成可交付步骤、证据、边界和成本，才开始成为产品。

能力产品化不是“把我会的都录成课”。

它至少经过七步：

```text
能力证据
→ 用户任务
→ 适用条件
→ 结果承诺
→ 交付机制
→ 成本容量
→ 验证与更新
```

## 一、先找任务，不先选载体

“我会做内容”太大。

可以继续拆成：

- 找到值得验证的对标。
- 判断账号当前断点。
- 把口述经验整理成脚本。
- 建立小团队内容流程。
- 用数据决定下一轮修改。

任务不同，产品也不同。

一份诊断、一套工具、一次工作坊和长期代运营，解决的不是同一层问题。

## 二、最小交付单元

先找到一个用户使用后能够检查的最小变化。

例如：

- 从“我不知道问题在哪”到得到一份断点诊断。
- 从“只有零散经历”到完成一张资产证据表。
- 从“选题靠感觉”到获得一组有来源和验证假设的选题。

最小单元越清楚，越容易测试。

## 三、标准化与定制化

可以标准化：

- 定义。
- 判断顺序。
- 问卷。
- 模板。
- 质检标准。
- 常见分支。

通常需要定制：

- 目标取舍。
- 具体人群与项目判断。
- 高风险决策。
- 跨环节冲突。
- 现场反馈与责任协调。

不能标准化的部分如果被伪装成模板，用户会得到形式完整、现实无效的答案。

## 四、从能力到产品的五项检查

1. 有重复证据，不只一次偶然成功。
2. 用户能够识别任务和结果。
3. 交付者能解释关键步骤和失败条件。
4. 时间、人力和工具成本可承受。
5. 结果承诺与控制范围一致。

## 五、案例｜内容诊断

“会判断内容”仍不是产品。

产品化以后需要明确：

- 输入：账号、目标、样本、数据、产品与历史动作。
- 过程：阶段判断、内容诊断、断点定位、优先级排序。
- 输出：结论、证据、修改方案和七天实验。
- 边界：不代写、不保证流量、资料不足时降级。

这时能力才从个人直觉变成可交付服务。

## 六、反例

把自己十年经验录成六十节课，却没有说明哪类用户先学哪一节、要完成什么任务、怎样判断学会。

这是知识归档，不一定是产品。

## 七、输出标准

- 能力证据等级。
- 目标任务。
- 最小交付单元。
- 标准步骤和定制节点。
- 所需输入与用户责任。
- 成本、容量和禁区。

## 八、来源与冲突处理

- 个人资产模块提供能力证据与归因前提。
- 价值主张支持能力必须对应用户任务。
- 顾客价值支持交付不是单方展示能力。
- 本原子拒绝“会做就能教”和“内容越多产品越完整”。
