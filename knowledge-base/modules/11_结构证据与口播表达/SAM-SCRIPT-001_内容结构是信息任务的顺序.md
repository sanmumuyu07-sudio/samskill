# 内容结构是信息任务的顺序

## 叁木判断

结构不是 PAS、清单或故事这些模板名。结构是用户从“现在怎么想”走到“看完后怎么想、怎么做”必须经过的信息顺序。

## 为什么

创作者常按自己的发现顺序写：先交代背景，再讲过程，最后才说结论。但用户没有义务陪你复原思考过程。也有人反过来，第一句抛结论，后面只换说法重复。两者都没有完成理解任务。

真正的结构至少要回答：用户先知道什么，才听得懂下一步；哪个疑问必须先关闭；哪个证据要在主张之后出现；结尾要留下判断还是动作。

## 判断方法

先写一句：“这条内容要让____的人，从____理解，走到____判断，并完成____动作。”

再为每一段标注任务：识别相关、暴露问题、解释机制、提供证据、处理异议、给出行动。没有任务的段落不因写得好而保留。

## 边界与反例

相同信息可以有不同顺序。决策简报适合快速给结论；人物故事可能先让用户经历冲突；避坑内容可能先呈现损失。判断标准不是“像不像某个模板”，而是用户是否能用较低成本完成预期理解。

## 输出标准

一份内容任务句、段落任务表、信息依赖关系和可删除段落清单。

## 验证

让未参与创作的人复述：这条内容解决什么、核心判断是什么、凭什么、下一步是什么。复述偏离时，先查结构，不先怪用户。
