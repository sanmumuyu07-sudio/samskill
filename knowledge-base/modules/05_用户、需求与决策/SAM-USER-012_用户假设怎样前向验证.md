# 用户假设怎样前向验证

## 叁木判断

> 用户画像是一个需要预测未来行为的假设，不是对过去材料的漂亮总结。不能产生可检验预测的画像，无法指导内容与产品。

## 一、把描述改成预测

弱描述：

“这群人有判断力但缺系统。”

可检验版本：

“已有真实项目、能提供过往样本但缺复盘规则的人，面对阶段诊断内容时，会比基础工具内容更愿意提交项目资料并完成一次自查。”

## 二、前向验证四步

1. 写一个具体场景和任务假设。
2. 写如果它成立，用户会出现什么行为。
3. 设计内容、访谈、预约、试用或付费实验。
4. 提前写支持、反对和停止阈值。

## 三、一次只改一个关键关系

同时改标题、人群、产品和价格，结果无法归因。

优先验证最危险关系：

- 用户是否有这个任务。
- 是否在此刻优先处理。
- 是否愿意行动。
- 产品机制是否有用。

## 四、允许被推翻

用户假设被推翻，不等于用户“口是心非”。

可能是：

- 场景写错。
- 样本找错。
- 表达不清。
- 产品不适配。
- 行为成本过高。
- 需求本来就弱。

## 五、案例

假设：有专业经验但没有公开证明的人，需要一人媒体方法。

可测试：

- 发布“经历不等于资产”的自查工具。
- 观察哪些人愿意填写真实项目。
- 访谈完成与未完成者。
- 提供小范围公共证明实验。
- 记录行动而不只看点赞。

## 六、反例

内容爆了以后，倒推“我们的人群画像非常精准”。

高传播可能来自更广泛情绪，并不能证明目标用户完成了预期行为。

## 七、输出标准

- 原假设。
- 可观察预测。
- 样本、动作和阈值。
- 支持与反证。
- 修改后的假设。
- 下一轮只改什么。
