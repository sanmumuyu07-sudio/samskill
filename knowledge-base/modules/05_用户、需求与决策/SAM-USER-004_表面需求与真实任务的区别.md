# 表面需求与真实任务的区别

## 叁木判断

> 用户说出口的问题是研究入口，不是必须被否定的假需求。所谓“更深任务”只能作为假设，由事件、行为和替代方案逐步支持。

## 一、为什么用户原话不完整

- 只描述眼前动作。
- 没有时间回忆完整过程。
- 缺少专业语言。
- 不愿暴露风险和关系。
- 自己也在用某种解释降低矛盾。

不完整不等于错误。

## 二、追问不要只问抽象为什么

连续问“为什么”容易把用户带向一个听起来深刻的答案。

更可靠的追问是：

1. 最近一次发生在什么时候。
2. 当时先做了什么。
3. 为什么没有继续原方案。
4. 谁受到影响。
5. 你怎样判断这件事解决了。
6. 还有什么不同解释。

## 三、事实、解释与假设分开

用户说“我不会写文案”是原话。

连续三个月没有发布是行为事实。

“害怕被同事评价”如果没有直接材料，只能是解释假设。

三者不能写成一句确定结论。

## 四、案例

表面问题：“我想找一个爆款模板。”

可能任务包括：

- 明天必须交稿，需要降低时间成本。
- 不知道怎样判断好坏，希望有人承担决策。
- 连续失败，想用模板降低风险。

必须通过最近一次交稿、既有流程和失败行为区分。

## 五、反例

用户问剪辑方法，操盘者一路追问，最后得出“你真正想要自由和价值”。

答案也许有共鸣，却未必能解释用户为什么今天搜索这一功能。

## 六、输出标准

- 用户原话。
- 可观察行为。
- 当前任务假设。
- 支持与反对证据。
- 至少一个替代解释。
- 下一项追问或实验。
